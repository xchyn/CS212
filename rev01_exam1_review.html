Exam 1 Review

Everything from Lecture 1 to Lecture 10, compressed into what you actually have to be able to do in fifty minutes.

What Exam 1 Covers

Exam 1 is fifty minutes, closed book — no notes, no computer, no calculator — and it is four problems worth forty-five points. The four have been the same four kinds of question for years:

  • Write a complete program that reads something with Scanner and does something to it with String methods (10 pts).
  • What is the output? — a program with eight or ten marked lines, one point each (10 pts).
  • Write a complete class from a specification: instance variables, constructor, a few methods (15 pts).
  • Find the three errors in a numbered listing, and give a corrected version of each line (10 pts).

The material that is fair game, with the lecture it came from:

  1. Lecture 1. Bytecode and the JVM; the class / main skeleton and the file-name rule; javac then java; the eight primitive types; integer division; what + does when a String is involved; loops and if.
  2. Lecture 2. Writing a method: the title line word by word, parameters, return types, arguments passed by value; overloading; calling a method that lives in another class; recursion and base cases.
  3. Lecture 3. Arrays: declaring and creating, length, indexing and ArrayIndexOutOfBoundsException, the for-each loop, arrays as parameters, two-dimensional arrays; reading from the keyboard with Scanner.
  4. Lecture 4. String as an object: the string pool, == versus .equals, immutability, and length(), charAt, substring, indexOf, contains, trim, replace, toUpperCase, split.
  5. Lecture 5. File objects; reading a file with Scanner; writing one with PrintWriter; close(); the throws FileNotFoundException clause.
  6. Lecture 6. ArrayList: the import, the type in angle brackets, add, get, set, size, contains, both remove methods, and removing while you loop.
  7. Lecture 7. Classes and objects: instance variables, private, constructors, this, getters and setters, toString, and objects stored inside objects.
  8. Lecture 8. References and aliasing; null and the NullPointerException; what == compares for objects; passing an object to a method; mutating an object versus rebinding a variable.
  9. Lecture 9. Overriding equals and toString; static fields and methods; why main is static and why this is not available in it; final and static final.
  10. Lecture 10. Turning an English problem description into a set of classes: finding the nouns, deciding what each class knows and what it can do, and recognising "has-a" — one object holding a reference to another. Not asked as code, but it is the reasoning behind Problem 3.

Nothing after Lecture 9 is on this exam. Inheritance, polymorphism, interfaces, GUIs and exceptions all come later in the semester, so if a practice problem you find mentions extends or implements, it belongs to Exam 2, not this one.

1.Lectures 1 and 2 — the language, methods and recursion

The first two lectures were about getting C++ knowledge into Java shape. Nothing here is conceptually new to you; the points get lost on details. A Java program is a class containing public static void main(String args[]), and the file has to be named after the public class. javac Name.java compiles and says nothing when it works; java Name runs, and takes a class name. The eight primitives are byte, short, int, long, float, double, char and boolean, and a condition must be a real boolean — if (n = 5) is a compile error in Java, not a silent bug as in C++.

Lecture 2 added everything about methods:

  • The title line is public static, then the return type, then the method name, then the parameter list in parentheses. You will be asked to write title lines from a main that calls them — read each argument to get the parameter type, and read what is done with the result to get the return type.
  • A method that promises a value must return one on every path. A void method cannot return one at all.
  • Arguments are copied. Assigning to a parameter inside a method never changes the caller's variable. (For objects the copy is a copy of the reference, which is the whole subject of Lecture 8.)
  • Overloading means two methods with the same name and different parameter lists. The return type is not part of the deal.
  • Recursion needs a base case that is actually reached. n / 10 chops the last digit off an integer and n % 10 is the last digit; between them you can take any number apart, which is exactly what evenUp in Practice Problem 7 needs.
Common Mistake— the ones that cost points from Lectures 1 and 2
  • Integer division. If both operands of / are integers, the fraction is thrown away. (a + b + c) / 3 with a = 90, b = 85, c = 78 is 84, and storing it in a double does not help — the damage is done before the assignment:
int a = 90, b = 85, c = 78;
double average = (a + b + c) / 3;
System.out.println(average);
84.0

Write / 3.0, or cast an operand: (double) (a + b + c) / 3. Casting the finished result, (double) ((a + b + c) / 3), is still 84.0.

  • + is concatenation from the first String onward. "Total: " + a + b with a = 90, b = 85 prints Total: 9085; you wanted "Total: " + (a + b), which prints Total: 175. Scan left to right and ask at every + whether a String has appeared yet.
  • A char is a number. 'C' + 2 is 69, because there is no String anywhere in that expression. "" + 'C' + 2 is C2.
  • The file name must match the public class, capital letters included.
  • Overloading on the return type alone is not overloading. Two methods with identical parameter lists are simply a duplicate:
Over.java:3: error: method size(int[]) is already defined in class Over
    public static double size(int a[]) { return a.length; }
                         ^
1 error
  • A recursion with no reachable base case does not loop forever; it dies with a StackOverflowError. If your recursive method is called with n and recurses on n - 1, check what happens for negative n.
Practice Problem 1— added for these notes

What does each marked line print? This is Lecture 1 and Lecture 2 in one program, and it is exactly the format of Problem 2 on the real exam.

Review1.java

public class Review1 {
    public static int fact(int n) {
        if (n <= 1) return 1;
        return n * fact(n - 1);
    }

    public static double half(int n) {
        return n / 2;
    }

    public static void main(String args[]) {
        int a = 7, b = 2;
        char c = 'C';

        System.out.println(a / b + " " + a % b);     // line (a)
        System.out.println("sum = " + a + b);        // line (b)
        System.out.println("sum = " + (a + b));      // line (c)
        System.out.println(half(a));                 // line (d)
        System.out.println(fact(4));                 // line (e)
        System.out.println(c + 2);                   // line (f)
        System.out.println("" + c + 2);              // line (g)
    }
}

(a) Line (a).

3 1. 7 / 2 is integer division giving 3, and 7 % 2 is the remainder 1. The " " in the middle makes the whole thing a String, but / and % bind tighter than +, so both divisions happen first.

(b) Line (b).

sum = 72. "sum = " + a is already a String, so + b appends the character 2 after the character 7. No addition happens anywhere on this line.

(c) Line (c).

sum = 9. The parentheses force 7 + 2 to be numeric addition before the concatenation.

(d) Line (d).

3.0. Declaring half as returning a double does not change what happens inside it: n / 2 is int / int, which is 3, and widening 3 to a double on the way out gives 3.0. This is the averaging bug wearing a different hat — the fix is return n / 2.0;.

(e) Line (e).

24. fact(4) is 4 × fact(3) = 4 × 3 × fact(2) = 4 × 3 × 2 × fact(1), and fact(1) hits the base case and returns 1. 4 × 3 × 2 = 24.

(f) Line (f).

69. 'C' is 67 in Unicode, and with no String in sight + means addition.

(g) Line (g).

C2. The empty String at the front turns the first + into concatenation, so the char is converted to text and the 2 is appended.

The whole program, run:

3 1
sum = 72
sum = 9
3.0
24
69
C2

Things to notice across all seven parts. Five of the seven lines are about one question: at this +, has a String appeared yet? Annotate the type of every subexpression as you read — write a small int or String above each operator — and these become bookkeeping instead of guesswork. Lines (b) and (c) differ only by a pair of parentheses, and on the real exam that pair is worth a point.

Key Idea— if you can only do one thing for Lectures 1 and 2

Take any expression that mixes int, double, char and String and write the type of each subexpression above it before you write the answer. Every point Lecture 1 and Lecture 2 are worth on this exam comes down to knowing the type of what you are looking at.

2.Lectures 3 and 4 — arrays, Scanner and String

These two lectures supply the raw material for the "write a complete program" problem, which is always worth ten or fifteen points and is always some version of read text from the user, take it apart, put something back together.

From Lecture 3, the array facts: int a[] = new int[5]; creates five slots initialised to zero, indexed 0 through 4; the size is fixed once created and lives in the field a.length with no parentheses; going outside the range is an ArrayIndexOutOfBoundsException at run time, not a compile error. int a[][] is an array of arrays, so the number of rows is a.length and the length of row r is a[r].length. An array parameter is a reference, so a method that changes arr[i] changes the caller's array — that is why shorten and setToFive can be void. Scanner in = new Scanner(System.in); gives you nextInt, nextDouble, next (one token) and nextLine (the rest of the line).

From Lecture 4, the String facts. A String is an object, and everything surprising follows from that:

  • "java" == "java" is true because both literals come from the string pool, but "java" == new String("java") is false. Content comparison is .equals, and case-insensitive content comparison is .equalsIgnoreCase.
  • Strings are immutable. s.toUpperCase() does not change s; it returns a new string. If you do not assign the result, nothing happened.
  • The methods you are expected to know cold: length(), charAt(i), substring(from), substring(from, to) (to is excluded), indexOf, contains, trim, replace, toUpperCase, toLowerCase, split, compareTo, equals.
Common Mistake— the ones that cost points from Lectures 3 and 4
  • length versus length(). An array has a field; a String has a method. Getting it backwards is a compile error both ways round, and it is the single most common typo in this course:
Len.java:5: error: cannot find symbol
        System.out.println(s.length);
                            ^
  symbol:   variable length
  location: variable s of type String
Len.java:6: error: cannot find symbol
        System.out.println(a.length());
                            ^
  symbol:   method length()
  location: variable a of type int[]
2 errors
  • The inner bound of a two-dimensional loop. Writing col < numbers.length instead of col < numbers[row].length compiles, runs, and prints a wrong number. On {{1, 2, 3, 4}, {0, 1, 2, 3}} it gives total = 4 instead of 16.
  • == on strings that came from the user. A string read by Scanner is built at run time and is never the pooled literal, so if (answer == "yes") is false even when the user typed yes. Use answer.equals("yes").
  • Forgetting that String methods return a new string. s.trim(); on its own line does nothing at all. Write s = s.trim();.
  • substring(a, b) excludes b. "Problem".substring(2, 3) is "o", one character, not two.
  • nextInt() followed by nextLine(). nextInt leaves the newline in the buffer, so the next nextLine returns an empty string. Either read the leftover line and throw it away, or read everything with nextLine and convert.
  • Off the end of an array. A loop written i <= a.length throws ArrayIndexOutOfBoundsException on its last pass. The last valid index is a.length - 1.
Practice Problem 2— added for these notes

Seven lines of String and array work. Give the output of each.

Review2.java

public class Review2 {
    public static void main(String args[]) {
        String s = "  CSCI 212  ";
        String t = s.trim();
        String w[] = t.split(" ");

        System.out.println(t.length());                 // line (a)
        System.out.println(t.charAt(t.length() - 1));   // line (b)
        System.out.println(t.substring(5));             // line (c)
        System.out.println(t.indexOf("2"));             // line (d)
        t.toUpperCase();                                // line (e)
        System.out.println(t);                          // line (f)
        System.out.println(w.length + " " + w[1]);      // line (g)
    }
}

(a) Line (a).

8. trim removed the two spaces at each end, leaving CSCI 212 — four letters, one space, three digits.

(b) Line (b).

2. t.length() - 1 is 7, and index 7 is the last character. Indexing a String starts at 0 exactly as it does for an array, which is why length() - 1 is the standard way to reach the last character.

(c) Line (c).

212. The one-argument substring takes everything from index 5 to the end. C(0) S(1) C(2) I(3) space(4) 2(5).

(d) Line (d).

5. indexOf returns the index of the first occurrence, and the first 2 is at index 5. Had the character not been there at all it would have returned -1, which is the value you must test for.

(e) Line (e), and then line (f).

Line (e) prints nothing — it is not a println. It computes the upper-case version of t and throws it away, because String objects are immutable and toUpperCase returns a new object. Line (f) therefore prints CSCI 212, unchanged.

(f) Line (g).

2 212. split(" ") cut CSCI 212 at the single space into a two-element array, so w.length is 2 and w[1] is "212".

The whole program, run:

2
212
5
CSCI 212
2 212

Things to notice across all six parts. Line (a) uses t.length() with parentheses and line (g) uses w.length without them, in the same program, and both are correct — t is a String and w is an array. If you cannot say instantly which of the two a name refers to, you cannot answer the question, so on the exam write S or [] next to each variable as you read the declarations.

Line (e) is the trap that appears on nearly every version of this question. Any String method call whose result you do not store is dead code.

Key Idea— if you can only do one thing for Lectures 3 and 4

Be able to write, from memory and without hesitating, the skeleton that reads a line from the user, splits it into words, and loops over the words: Scanner in = new Scanner(System.in); then String line = in.nextLine(); then String w[] = line.split(" "); then for (String x : w) { ... }. Three of her four "write a complete program" problems are that skeleton with a different body.

3.Lectures 5 and 6 — files and ArrayList

These two lectures carry the fewest exam points, but they carry the sharpest traps, and a "find the errors" problem loves them.

Files, from Lecture 5. A File object is a name, not the contents: creating one never touches the disk, and f.exists() is how you find out whether anything is there. To read, wrap a File in a Scanner — Scanner in = new Scanner(new File("scores.txt")); — and then use exactly the methods you already use for keyboard input, usually while (in.hasNextLine()). To write, PrintWriter out = new PrintWriter("report.txt"); and then out.println(...) exactly like System.out. Both of those constructors can fail, so the method containing them needs throws FileNotFoundException (or a try/catch, which is Lecture 20).

Lists, from Lecture 6. ArrayList is the array that grows: import java.util.ArrayList;, then ArrayList<String> names = new ArrayList<String>();, then add, get(i), set(i, v), size(), contains, indexOf, remove, isEmpty, clear. The type in the angle brackets must be a class, so a list of whole numbers is ArrayList<Integer>, never ArrayList<int>. And notice how the three collections you now know report their size: an array uses a.length, a String uses s.length(), an ArrayList uses list.size(). Three containers, three spellings.

Common Mistake— the ones that cost points from Lectures 5 and 6
  • new Scanner("scores.txt") compiles. That is what makes it dangerous. Scanner has a constructor that takes a String and reads from that text, so this program never opens a file — it prints the file name:
Scanner in = new Scanner("scores.txt");
System.out.println(in.next());
scores.txt

To read a file you must pass a File: new Scanner(new File("scores.txt")).

  • Forgetting out.close(). A PrintWriter buffers. Without the close() the program ends, the buffer is discarded, and the file on disk is zero bytes long — no error message anywhere. If your output file is mysteriously empty, this is why, every time.
  • list.remove(20) on an ArrayList<Integer> removes index 20, not the value 20, because remove(int) and remove(Object) are both real methods and the int wins. See Practice Problem 3 below.
  • Removing inside a for-each loop. Usually you get a ConcurrentModificationException; occasionally — when you remove the second-to-last element — you get no exception and a quietly wrong answer, which is worse. Loop backwards with an index instead.
  • ArrayList<int> does not compile. Use ArrayList<Integer>, and remember that == on two Integer objects compares references.
Practice Problem 3— added for these notes

This program is meant to delete the value 20 from the list and print what is left. It compiles cleanly.

Review3.java

import java.util.ArrayList;

public class Review3 {
    public static void main(String args[]) {
        ArrayList<Integer> nums = new ArrayList<Integer>();
        nums.add(10);
        nums.add(20);
        nums.add(30);
        nums.add(20);

        nums.remove(20);          // meant to delete the value 20

        System.out.println(nums);
    }
}

(a) What happens when you run it?

It crashes before printing anything:

Exception in thread "main" java.lang.IndexOutOfBoundsException: Index 20 out of bounds for length 4
	at java.base/jdk.internal.util.Preconditions.outOfBounds(Preconditions.java:100)
	at java.base/jdk.internal.util.Preconditions.outOfBoundsCheckIndex(Preconditions.java:106)
	at java.base/jdk.internal.util.Preconditions.checkIndex(Preconditions.java:302)
	at java.base/java.util.Objects.checkIndex(Objects.java:385)
	at java.base/java.util.ArrayList.remove(ArrayList.java:551)
	at Review3.main(Review3.java:11)

ArrayList has two remove methods: remove(int index) and remove(Object o). The literal 20 is an int, so Java chooses remove(int) without a second thought and asks for element number 20 of a four-element list.

(b) Fix the one line so the program deletes the value 20, and give the output of the fixed program.

Force the argument to be an object so that remove(Object) is chosen:

nums.remove(Integer.valueOf(20));   // delete the value 20
[10, 30, 20]

Things to notice across both parts. Only the first matching element is removed — the second 20, now at index 2, survives. remove(Object) returns a boolean saying whether it found anything, and remove(int) returns the element it took out, so even the return types differ.

(Integer) 20 and Integer.valueOf(20) both work; the cast reads more like exam Java, the valueOf call is what you will see in professional code. What does not work is declaring int target = 20; and writing nums.remove(target) — that is still an int.

Key Idea— if you can only do one thing for Lectures 5 and 6

Memorise the two file one-liners — new Scanner(new File(name)) to read, new PrintWriter(name) plus a matching close() to write — and the three ways to ask how big something is: a.length, s.length(), list.size().

4.Lectures 7, 8 and 9 — classes, references and static

This is where most of the exam lives. The fifteen-point "write a class" problem comes from Lecture 7, the ten-point "what is the output" problem is almost always really about Lecture 8, and Lecture 9 supplies the static question that shows up inside the find-the-errors problem.

Lecture 7 — writing a class. The recipe never changes, and you should be able to produce it under time pressure without thinking:

Procedure— the fifteen-point class, in order
  1. public class Name { — and if the specification says "exactly two instance variables", write exactly two.
  2. The instance variables, each private, each on its own line.
  3. The constructor: same name as the class, no return type, one parameter per instance variable, body assigning this.field = parameter;.
  4. The methods the specification asks for, and no others. A getter returns the field; a setter takes a value and assigns it.
  5. toString, returning — not printing — the exact String the specification shows.

Then re-read the specification and count: did it say four methods, or six? She grades against that number.

Lecture 8 — references. A variable of a class type does not hold the object; it holds a reference to it. Four consequences, and every output problem she sets is built from them:

  • Point b = a; makes an alias. There is still one object. Changing it through b changes what you see through a.
  • == on two object variables asks "same object?", not "same contents?".
  • A reference that points at nothing is null, and calling a method on it is a NullPointerException. An array of objects starts full of nulls: new Pet[3] gives you three empty slots, not three pets.
  • Passing an object to a method copies the reference. The method can change the object (y.raiseSalary(200) is visible to the caller) but cannot change which object the caller's variable points at (x = y; inside the method is invisible outside it). Mutating and rebinding are two different things.

Lecture 9 — equals, toString and static. equals and toString are inherited by every class from Object, and the versions you inherit are useless: equals just does ==, and toString prints something like Point@6d06d69c. You replace them. The signature of equals is public boolean equals(Object other) — taking Object, not your own class — and the body checks instanceof, casts, and compares fields. A static field is one copy shared by the whole class (a counter of how many objects were made); a static method belongs to the class and can be called without an object, which is why main is static and why this means nothing inside it.

Common Mistake— the ones that cost points from Lectures 7, 8 and 9
  • Calling an instance method on the class name. Circle.area() is not a thing; area needs a particular circle. This is error number one on the Spring 2025 find-the-errors problem:
StaticCall.java:9: error: non-static method area() cannot be referenced from a static context
        System.out.println(Circle2.area());
                                  ^
1 error
  • Using this inside main. Same rule from the other side — a static method has no object, so there is no this:
ThisStatic.java:4: error: non-static variable this cannot be referenced from a static context
        System.out.println(this.x);
                           ^
1 error
  • Giving the constructor a return type. public void Pet(String s) is not a constructor. It is an ordinary method that happens to be spelled like the class, it is never called by new, and the compiler will not warn you.
  • Writing any constructor removes the free one. Once you write Circle(double r, Point c), new Circle() no longer compiles. If the specification wants both, write both.
  • == where you meant .equals. Two Point objects with the same coordinates are == false and .equals true — provided you wrote equals.
  • Overload instead of override. This one is silent and it is the trap Lecture 9 spends the most time on. Writing public boolean equals(Point p) gives you a second, unrelated method; the inherited equals(Object) is still there, and the moment your object is held in an Object variable or put in a list, the inherited one is what runs:
Point9 a = new Point9(1, 2);
Point9 b = new Point9(1, 2);
Object o = b;
System.out.println(a.equals(b));   // the overload runs
System.out.println(a.equals(o));   // the inherited Object.equals runs
true
false

The parameter type must be Object.

  • A "reset" method that resets nothing. Assigning to a parameter inside a method — public static void reset(Point p) { p = new Point(0, 0); } — rebinds the local copy of the reference and the caller sees nothing. To change the object, call a method on it or assign to its fields.
  • static where the field should be per-object. If balance is static, every account in the program shares one balance. Ask yourself: is there one of these per object, or one for the whole class?

public class Counter {

Key Idea— if you can only do one thing for Lectures 7, 8 and 9

Practise writing a small class from a written specification — private fields, constructor with this, getters, toString — on paper, against a clock, until it comes out right the first time. That single skill is fifteen of the forty-five points, and it is the only problem on the exam where you cannot recover the marks by being clever.

5.Lecture 10 — turning a description into classes

The last class before this review was not new syntax. It was the thing all the syntax is for: reading a paragraph of English and deciding what the classes are. That skill is what Problem 3 on every CSCI 212 exam is really testing — the specification is given in words, and you have to turn it into instance variables, a constructor and methods.

Procedure— from a description to a class
  1. Underline the nouns. The important ones become classes; the rest become instance variables. "A ticket has an officer, a car and a fine" gives you a class and three fields.
  2. Give each field a type. A count is an int, money is a double, a name or a plate is a String, a yes/no is a boolean. Anything that is itself one of your nouns is a reference to that class.
  3. Make the fields private. Always. Then add only the getters the problem actually asks for.
  4. Underline the verbs. Those are the methods. "The meter runs down", "the officer writes a ticket", "the account computes interest".
  5. Write the constructor last, once you know what the fields are. Its parameters are whatever the caller must supply.
Key Idea— "has-a"

When one of your classes stores an object of another, that is has-a (composition). A ParkedCar has-a ParkingMeter; a Circle has-a Point for its centre; a SavingsAccount on the Summer 2026 midterm is-a BankAccount, which is a different relationship and belongs to Lecture 12. On this exam, every relationship you meet is has-a.

And remember Lecture 8: the field holds a reference. If the caller keeps its own reference to the same Point you stored, changing it changes your object too.

Practice Problem 5 — Fill an array with random numbers (from Exam 1 Practice Problems)

Write a function called randFill that fills the entries of an array with random integers in the range from 10 to 99 inclusive. You should use a standard Java method to generate the values, and your solution should use no more than six lines of code. Here is a program that uses it:

public class P4 {
    public static void main(String args[]) {
        int x[];
        x = randFill(5);
        for (int i = 0; i < 5; i++)
            System.out.print(x[i] + " "); // prints 5 random numbers
        System.out.println();             // such as 93 73 12 69 40
    }
}

Plan. Read the calling code before you write anything: x = randFill(5) assigns to an int[], and the argument is the size. So the title line has to be public static int[] randFill(int size) — the method creates and returns the array rather than filling one it was given. Then the range. new Random().nextInt(90) produces 0 through 89, and adding 10 shifts that to 10 through 99, which is exactly the ninety values asked for. Count them: 99 − 10 + 1 = 90.

P4.java

import java.util.Random;

public class P4 {
    public static int[] randFill(int size) {
        Random rand = new Random();
        int arr[] = new int[size];
        for (int i = 0; i < size; i++)
            arr[i] = rand.nextInt(90) + 10;
        return arr;
    }

    public static void main(String args[]) {
        int x[];
        x = randFill(5);
        for (int i = 0; i < 5; i++)
            System.out.print(x[i] + " ");
        System.out.println();
    }
}

Two real runs. These values are random, so yours will differ — what you should check is that every number has two digits:

78 25 91 79 48
68 33 12 90 49

Things to notice. nextInt(n) is exclusive of n. The commonest wrong answers are rand.nextInt(99) + 10, which can reach 107, and rand.nextInt(89) + 10, which never reaches 99. The reliable way to build the expression is: nextInt(high - low + 1) + low.

The import java.util.Random; matters and is worth a mark. Random lives in java.util alongside Scanner and ArrayList.

An alternative that needs no import at all is (int) (Math.random() * 90) + 10, since Math.random() returns a double in the range 0.0 up to but not including 1.0. Both are acceptable; the cast is easy to forget, which is why Random is the safer answer under time pressure.

Notice finally that the method could not have been written to fill an array passed in as a parameter and be used as x = randFill(5) — the calling code decides your title line. Always write the title line last, from the call, not first, from the description.

Practice Problem 6 — Rows with a positive sum (from Exam 1 Practice Problems)

Write a function called positiveRows that returns the number of rows of a two-dimensional array that have a positive sum. The array contains double values. Here is a program that uses it; the answer is 1 because only the first row has a positive sum.

public class P7 {
    public static void main(String args[]) {
        double x[][] = { { 1.0, 6.0, 3.0, -5.0, -4.0, 2.0 },
                         { -4.0, -4.0, -4.0, 4.0, 2.0, 4.0 } };
        System.out.println(positiveRows(x)); // prints 1
    }
}

Plan. The call is used as an argument to println and the comment says it prints 1, so the return type is int and the parameter is double[][]. The body is the standard nested loop with one thing added: the running sum has to be reset at the top of every row, so it is declared inside the outer loop, not outside it. Then one if after the inner loop finishes.

P7.java

public class P7 {
    public static int positiveRows(double a[][]) {
        int count = 0;
        for (int i = 0; i < a.length; i++) {
            double sum = 0;
            for (int j = 0; j < a[i].length; j++)
                sum += a[i][j];
            if (sum > 0) count++;
        }
        return count;
    }

    public static void main(String args[]) {
        double x[][] = { { 1.0, 6.0, 3.0, -5.0, -4.0, 2.0 },
                         { -4.0, -4.0, -4.0, 4.0, 2.0, 4.0 } };
        System.out.println(positiveRows(x));
    }
}
1

Things to notice. Check the arithmetic yourself, because the exam wants you to: row 0 is 1 + 6 + 3 − 5 − 4 + 2 = 3, which is positive; row 1 is −4 − 4 − 4 + 4 + 2 + 4 = −2, which is not. So the answer is 1.

The inner bound is a[i].length, not a.length. Here the array has 2 rows and 6 columns, so writing a.length for the inner bound would visit only the first two entries of each row and give the wrong count — and it would compile and run without complaint. This is the same bug as Practice Problem 10(a) below, and it is on her list twice for a reason.

double sum = 0; inside the outer loop is the second half of the problem. Declare it outside and sum becomes a running total of every row so far: 3 after row 0, then 3 − 2 = 1 after row 1. Both are positive, so the method would answer 2. Reset your accumulator at the top of each row deliberately — and when you write any counting loop, ask which variables belong to the whole job and which belong to one row.

One more thing, because it is good exam practice. The two printed copies of this question describe the answer differently: one says the output is 2 "because only columns 1 and 3 have positive sum", the other says it is 1 "because only the first row has a positive sum". The code comment, // prints 1, agrees with the second, and the method is named positiveRows. When parts of a question disagree, follow the code and the method name, and write one sentence saying which reading you took. That sentence protects your marks.

Practice Problem 7 — Increase the first even digit (from Exam 1 Practice Problems)

Write a function called evenUp that returns the result of increasing the first even digit in a positive integer parameter by 1. Your solution should use no more than ten lines of code, and it may return any convenient value if the parameter is not positive.

public class P5 {
    public static void main(String args[]) {
        System.out.println(evenUp(1232)); // prints 1332 only the first even 2 changes
        System.out.println(evenUp(1332)); // prints 1333
        System.out.println(evenUp(1333)); // prints 1333 no even digit to change
        System.out.println(evenUp(22));   // prints 32
        System.out.println(evenUp(2));    // prints 3
    }
}

Plan. "First" means leftmost, and the easy end of a number to get at is the right end — n % 10 is the last digit and n / 10 is everything else. So work right to left with recursion and let the recursion find the leftmost one for you: deal with n / 10 first, and only if that call reported no change do you consider the last digit yourself.

How does a call report "I changed something"? Compare its answer with what it was given. If evenUp(n / 10) returns something bigger than n / 10, a digit further left was already bumped; glue the original last digit back on and stop. Otherwise, if the last digit is even, bump it. Otherwise return the number unchanged.

P5.java

public class P5 {
    public static int evenUp(int num) {
        if (num <= 0) return num;
        int rc = evenUp(num / 10);
        if (rc > num / 10) return rc * 10 + num % 10;
        if (num % 2 == 0) return num + 1;
        return num;
    }

    public static void main(String args[]) {
        System.out.println(evenUp(1232));
        System.out.println(evenUp(1332));
        System.out.println(evenUp(1333));
        System.out.println(evenUp(22));
        System.out.println(evenUp(2));
    }
}

Practice Problem 9 — The hundred lockers (from Exam 1 Practice Problems)

A school has 100 lockers and 100 students. All lockers are closed on the first day of school. As the students enter, the first student S1 opens every locker. The second student S2 begins with locker L2 and closes every other locker. Student S3 begins with L3 and changes every third locker — closing it if it is open, opening it if it is closed. S4 begins with L4 and changes every fourth locker, and so on, until S100 changes L100.

After all the students have passed through, some lockers are open and some are closed. L1 was changed only by S1, so it is open; L3 was changed by S1 and S3, so it is closed. Write a program that finds and displays all the lockers that end up open. The output should list them as L followed by a number, separated by exactly one space. Name your class Lockers; it should have just a static main. Use no more than fifteen instruction lines, not counting braces and blank lines. (Hint: use an array of 100 boolean values, all initially false, meaning closed.)

Plan. Two decisions carry the whole program. First, represent a locker by a boolean and represent "change it" by lockers[i] = !lockers[i]; — there is no need for an if, because flipping is exactly what ! does. Second, get the indexing right: locker L1 lives at index 0, so student s starts at index s - 1 and steps by s. Then print, adding 1 back to the index to recover the locker number.

The array is new boolean[100], and Java fills a new boolean array with false, so "all lockers are closed on the first day" needs no code at all.

Lockers.java

public class Lockers {
    public static void main(String args[]) {
        boolean lockers[] = new boolean[100];

        for (int student = 1; student <= 100; student++)
            for (int locker = student - 1; locker < 100; locker += student)
                lockers[locker] = !lockers[locker];

        for (int i = 0; i < lockers.length; i++)
            if (lockers[i]) System.out.print("L" + (i + 1) + " ");
        System.out.println();
    }
}
L1 L4 L9 L16 L25 L36 L49 L64 L81 L100

Things to notice. The answer is the perfect squares, and there is a reason. Locker n is touched once by every student whose number divides n, so it ends up open exactly when n has an odd number of divisors. Divisors normally come in pairs — 12 has 1×12, 2×6, 3×4 — and the only way to get an odd count is for one pair to be a repeat, which happens when n is a square: 36 has 6×6. You are not asked to prove this, but knowing the answer in advance is how you check that your loops are right.

lockers[locker] = !lockers[locker]; is the line to practise. The tempting alternative, if (lockers[locker]) lockers[locker] = false; else lockers[locker] = true;, is four lines doing the work of one and blows the fifteen-line budget.

The off-by-one is the other place people lose marks. Student 1 must touch every locker: index starts at 1 - 1 = 0 and steps by 1, so it visits every index — correct. Student 2 must start at L2, which is index 1, and step by 2, visiting L2, L4, L6 — correct. Check the first two students by hand and the rest follow.

The output ends with a trailing space after L100, because every locker is printed followed by " ". The specification says the lockers are separated by exactly one space, which this satisfies; if you wanted no trailing space you would print the space before every locker except the first.

Practice Problem 11 — The UPC check digit (from Exam 1 Practice Problems)

Retail products are identified by a Universal Product Code. The most common form has twelve decimal digits: the first identifies the product category, the next five the manufacturer, the next five the particular product, and the last is a check digit computed from the other eleven. Write a method checkDigit that takes a String of the first eleven digits and returns the check digit as an int.

The rule is the standard one: add the digits in the odd positions (the 1st, 3rd, 5th and so on), multiply that total by 3, add the digits in the even positions, and the check digit is whatever must be added to reach the next multiple of 10.

Plan. Walk the string with charAt, turn each character into a number, and add it to a running total — tripled if its index is even, since index 0 is the first position. Then convert "what must be added to reach the next multiple of 10" into arithmetic: that is 10 - sum % 10, except that when sum % 10 is already 0 the answer is 0, not 10 — so take the whole thing modulo 10 again.

UPC.java

public class UPC {
    public static int checkDigit(String str) {
        int sum = 0;
        for (int i = 0; i < str.length(); i++) {
            int digit = Character.getNumericValue(str.charAt(i));
            if (i % 2 == 0) sum += 3 * digit;
            else            sum += digit;
        }
        return (10 - sum % 10) % 10;
    }

    public static void main(String args[]) {
        System.out.println(checkDigit("03600029145"));
        System.out.println(checkDigit("01234567890"));
        System.out.println(checkDigit("00000000000"));
    }
}

5
0

Things to notice. The first test is a real barcode — 036000291452 is printed on a bar of soap — so the 2 is checkable against the physical world. That is worth doing whenever a problem describes something real.

Character.getNumericValue(c) converts the character '7' to the number 7. If you do not remember that method, c - '0' does the same job using only Lecture 1 material: a char is a number, and '7' - '0' is 55 − 48 = 7. Either is fine.

The last line is where the marks are. (10 - sum % 10) % 10 looks fussy until you feed it a sum ending in 0: 10 - 0 is 10, and a check digit of 10 is not a digit. The outer % 10 turns it back into 0. Any time you write "distance to the next multiple of n", write (n - x % n) % n and you will never meet that bug.

One caution about the printed solution to this question. The version in her answer key ends return sum % 10;, which is the running total's last digit rather than the amount needed to reach the next ten. On "01234567890" the two agree by coincidence — both give 5 — but on "03600029145" the key returns 8 where the real barcode says 2. Practice Problem 12 — Write the class Student (added for these notes)

This is the fifteen-point problem, in the exact shape she sets it. Write complete Java code for a class Student.

  • It should have exactly two private instance variables: name of type String and id of type int.
  • It should also keep a count of how many Student objects have been created, in a variable that belongs to the class rather than to any one student.
  • It must have exactly five methods: a constructor with two parameters; getName; getId; a method getCount that returns the number of students created and can be called without an object; and toString, returning a String of the form Ana (#1001).
  • Finally, override equals so that two students are equal when they have the same id.

Plan. Work down the specification in order and let it dictate the code. "Two private instance variables" is two private lines. "Belongs to the class rather than to any one student" is static, and it is initialised once, at the declaration, not in the constructor — the constructor's job is to add one to it. "Can be called without an object" is a static method. toString returns, it does not print. And equals takes an Object, not a Student, or it is a new method rather than a replacement for the inherited one.

Student.java

public class Student {
    private String name;
    private int id;
    private static int count = 0;

    public Student(String name, int id) {
        this.name = name;
        this.id = id;
        count++;
    }

    public String getName() { return name; }

    public int getId() { return id; }

    public static int getCount() { return count; }

    public boolean equals(Object other) {
        if (!(other instanceof Student)) return false;
        Student s = (Student) other;
        return id == s.id;
    }

    public String toString() {
        return name + " (#" + id + ")";
    }
}

public class StudentDemo {
    public static void main(String args[]) {
        Student a = new Student("Ana", 1001);
        Student b = new Student("Ana", 1001);
        Student c = a;

        System.out.println(a);
        System.out.println(a == b);
        System.out.println(a.equals(b));
        System.out.println(a == c);
        System.out.println("Students created: " + Student.getCount());
    }

Things to notice. this.name = name; is needed because the parameter and the field have the same name; without this. you would be assigning the parameter to itself, which compiles and silently leaves the field null. If the parameter were called n you could write name = n; and this would be optional. Using the same name and this. is the convention she uses in every solution key, so use it.

count is declared static and initialised at the declaration. Writing count = 0; inside the constructor would reset the counter every time a student is made, and getCount would answer 1 forever — a favourite exam trap.

getCount is called as Student.getCount(), on the class. It could also be written a.getCount() and would compile, but that reads as though the count belonged to Ana. Call static methods on the class name.

The equals signature is the one thing here you cannot guess. It is public boolean equals(Object other) — then instanceof to reject anything that is not a Student, then a cast, then compare. Writing public boolean equals(Student other) compiles and passes the test above, and then fails silently the moment a Student is compared through an Object variable or looked up in a list.

Finally, count the methods against the specification: constructor, getName, getId, getCount, toString — five, plus the equals the last bullet asked for. If you find yourself adding a setName, stop; she takes marks off for methods that were not requested.
