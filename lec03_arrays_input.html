1.Arrays: declaring one and creating one

Last time we learned to write a function as a Java static method: a title line of the form public static result_type method_name(parameters), called from main by name, from another class as ClassName.method(...), and from itself when it is recursive. Everything we write today gets passed to methods, so keep that shape in mind.

So far every variable we have declared holds exactly one value. If you need five test scores you declare five variables; if you need a hundred, you are in trouble. An array is Java's answer, and it is very close to the C++ array you already know — with one important difference we will get to in §2.

Definition— array

An array is a single variable that holds a numbered sequence of values, all of the same type. The values are called elements; the number identifying an element is its index, and indices start at 0.

An array of five int values has indices 0, 1, 2, 3 and 4 — there is no element 5. You read element i with a[i] and you write it with a[i] = value;.

Declaring an array and creating it are two separate things in Java, and the notes for today make the point twice: array declaration can be done in several ways, depending on when you want to allocate memory and initialize the array. Here are the forms.

FormWhat it does
int[] a;Declares the variable only. No memory for elements yet; a refers to nothing.
int a[];Exactly the same thing. The brackets may go after the type or after the variable name.
a = new int[5];Allocates room for five int values and fills them with the default value.
int[] a = new int[5];Declare and allocate on one line. The usual choice when you know the size but not yet the values.
int[] c = {3, 1, 4, 1, 5};An initializer list: declare, allocate and fill in one step. You do not write a size — Java counts the values for you.
a = new int[]{10, 20, 30};An initializer list used somewhere other than a declaration. The new int[] part is required here.
Key Idea— the size rule

The size must be given when you allocate memory, except when you use an initializer list — then the list itself supplies the size. Those are the only two possibilities. Writing a size in the declaration itself, as C does with int a[5];, is not Java.

Every element of a newly allocated array is set to a definite default value: 0 for the integer types, 0.0 for double, false for boolean, and null for anything that is an object. Java never hands you an array full of garbage the way C++ can.

Compiles. Four elements, every one of them 0. This is the "I know the size, I do not yet know the values" form, and it is the one you will use most.

(b) int q[] = {5, 6, 7, 8, 9};

Compiles. Five elements, already holding 5 through 9. The brackets after the variable name are legal; the missing size is not a mistake, because the initializer list supplies it.

(c) int r[10];

Does not compile — error: ']' expected. This is the C++ form. In Java the size belongs to new, not to the declaration. Write int[] r = new int[10];.

(d) int[] s; s = new int[]{1, 2};

Compiles. Two elements. The declaration and the allocation happen on separate lines, which is exactly what you need when the values are decided somewhere else — inside an if, say, or returned by a method.

Things to notice across all four parts. Every legal form answers the same two questions in some order: how big? and what is in it? If you answer "how big" with a number you use new type[n]; if you answer "what is in it" with a list, the size comes free. Trouble only starts when you try to answer both at once, or neither.

One more property of arrays, and it is the one that eventually pushes people towards ArrayList in Lecture 6: the size of an array is fixed once it is created. There is no way to append a sixth element to a five-element array. What you can do is build a bigger array and copy across.

Worked Example— "growing" an array, which really means replacing it

The variable a ends up describing a four-element array, but the three-element array it started with was never resized — a second array was built and a was pointed at it.

FixedSize.java

public class FixedSize {
    public static void main(String args[]) {
        int[] a = {3, 1, 4};
        System.out.println("a has " + a.length + " slots: " + a[0] + " " + a[1] + " " + a[2]);

        int[] bigger = new int[a.length + 1];
        for (int i = 0; i < a.length; i++) bigger[i] = a[i];
        bigger[a.length] = 1;

        a = bigger;

        System.out.print("a now has " + a.length + " slots:");
        for (int v : a) System.out.print(" " + v);
        System.out.println();
    }
}
a has 3 slots: 3 1 4 a now has 4 slots: 3 1 4 1

bigger[a.length] = 1; writes to index 3, which is the first slot past the end of the old array and the last slot of the new one. Writing it as a.length rather than 3 means the line stays correct if the original array changes size.

The old three-element array is now unreachable, and Java's garbage collector will reclaim it without being asked. That is the automatic memory management we met in Lecture 1 doing its job: in C++ this is where you would have had to delete[] the old array yourself.

2.length, indexing, and running off the end

Every Java array knows how big it is, and it will tell you. This is a real improvement on C++, where an array is just an address and you have to carry the size around in a separate variable.

Definition— the length property

length is a built-in property of every Java array: an int giving the number of elements the array can hold. You write it with no parentheses and no arguments:

a.length — the number of slots in the array a.

It is fixed at creation and can never be assigned to. a.length = 10; is a compile error.

Because indices start at 0, an array of length n has valid indices 0 through n - 1. Two idioms follow from that and you will write them thousands of times:

  • for (int i = 0; i < a.length; i++) — visit every element. Note <, not <=.
  • a[a.length - 1] — the last element.

This one appears on exams every single term, so learn it now and stop losing the point.

Quick Check 3.3

Given int[] nums = {10, 20, 30, 40}; and String word = "Queens";, write the expression that produces each value.

Things to notice across all four parts. The rule to carry into the exam is short: arrays have length, everything else has length(). If you cannot remember which is which under pressure, ask yourself whether the thing is an object. A String is an object and you ask it questions by calling methods. An array is not really an object with useful methods — its size is just a field you read.

What happens if you ask for an element that does not exist? Nothing good in C++ — the program reads whatever memory happens to be there and carries on. Java refuses, loudly.

Worked Example— one character wrong, at run time

This loop has <= where it should have <. It compiles perfectly — the compiler has no way to know how big the array is at that point. Before you reveal: how many lines does it print before something goes wrong?

Bounds.java

public class Bounds {
    public static void main(String args[]) {
        int[] a = {3, 1, 4, 1, 5};
        for (int i = 0; i <= a.length; i++) {
            System.out.println("a[" + i + "] = " + a[i]);
        }
    }
}
a[0] = 3 a[1] = 1 a[2] = 4 a[3] = 1 a[4] = 5
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5

Five correct lines, then the crash. That is the shape of every off-by-one: the program looks entirely healthy right up to the last iteration.

The message is unusually helpful, so read all of it. Index 5 is what you asked for. length 5 is what the array actually has. Since valid indices stop at length - 1, index 5 is one past the end — which points straight at the <= in the loop header. Java also prints a stack trace naming the file and line; that line number is the first place to look.

This is the security feature from Lecture 1 in action. The JVM checks every single array access at run time and refuses to read memory that is not yours. It costs a little speed and it buys you an entire category of bugs you will never have to hunt.

Quick Check 3.4

int[] a = new int[8]; For each expression say whether it is valid, and if not, what index it asks for and what the exception message would say.

(a) a[8]

Invalid at run time. Valid indices are 0 through 7. The message would read Index 8 out of bounds for length 8. This is the single most common array bug there is, and it comes from thinking of a[8] as "the eighth one" — it would be the ninth.

(b) a[a.length - 1]

Valid. a.length is 8, so this is a[7], the last element.

(c) a[-1]

Invalid: Index -1 out of bounds for length 8. Negative indices do not wrap around to the end the way they do in Python. You get this one by writing a[i - 1] inside a loop that starts at i = 0.

(d) a.length = 10;

Invalid, and this one the compiler catches: cannot assign a value to final variable length. An array's size is fixed when it is created, so there is nothing to assign to. If you need ten slots, create a new array of ten.

Things to notice across all four parts. Three of these fail at run time and one fails at compile time, and the difference is about what the compiler can know. It knows length is unassignable, because that is a fact about the type. It cannot know whether the value of i will be 8 when the program actually runs, so that check has to wait until run time. Get in the habit of asking, for any bug, "could the compiler possibly have known?"

3.Walking an array: for and for-each

The indexed loop is the one you already know, and it is the general tool:

for (int i = 0; i < a.length; i++) System.out.println(a[i]);

Java also has a second loop form, built specifically for "do something to every element". It is shorter, it cannot go out of bounds, and it appears in your instructor's own solutions, so you need to be able to read it.

Definition— the enhanced for loop (for-each)

for (int v : a) { ... } reads as "for each int v in a". On each pass, v is a fresh variable holding a copy of the next element, in order from index 0 to the end.

The type before the variable must match the element type of the array: int for an int[], String for a String[], double for a double[].

There is no index variable. If you need to know where you are, or you want to change the array, this loop cannot help you.

Worked Example— the two loops, and what for-each cannot do

The first half sums the array both ways. The second half is the interesting part: it tries to zero the array with a for-each loop, prints the result, then does the same job with an indexed loop. Predict both printed rows before you reveal.

ForEachDemo.java

public class ForEachDemo {
    public static void main(String args[]) {
        int[] scores = {90, 85, 78, 92, 66};

        int total = 0;
        for (int i = 0; i < scores.length; i++) total += scores[i];
        System.out.println("Total (indexed loop):  " + total);

        int total2 = 0;
        for (int s : scores) total2 += s;
        System.out.println("Total (for-each):      " + total2);

        System.out.println("Average:               " + total / (double) scores.length);

        for (int s : scores) s = 0;
        System.out.println("After 'for (int s : scores) s = 0;'");
        for (int s : scores) System.out.print(s + " ");
        System.out.println();

        for (int i = 0; i < scores.length; i++) scores[i] = 0;
        System.out.println("After 'scores[i] = 0;'");
        for (int s : scores) System.out.print(s + " ");
        System.out.println();
    }
}
Total (indexed loop):  411
Total (for-each):      411
Average:               82.2
After 'for (int s : scores) s = 0;'
90 85 78 92 66 
After 'scores[i] = 0;'
0 0 0 0 0

Both loops compute the same total, as they should. The line to stare at is the fourth: after for (int s : scores) s = 0; the array is completely unchanged.

Here is why. s is a brand-new int variable, created fresh on every pass, holding a copy of the element. Assigning to s overwrites the copy and then the copy is discarded. Nothing ever touched scores. The indexed version says scores[i] = 0, which names a slot inside the array, so that one really does write.

Note also total / (double) scores.length. Both total and scores.length are int, so without the cast this would be integer division and print 82 — exactly the trap from Lecture 1, wearing an array as a disguise.

Key Idea— which loop to use

Use the for-each loop when you only need to read every element, in order, and you do not care where you are. Use the indexed loop when you need to write into the array, when you need the index itself, when you want to go backwards, or when you want to stop early.

Quick Check 3.5

Write a complete program Reverse.java that stores 3, 1, 4, 1, 5 in an array and prints the elements in reverse order on one line, separated by spaces. Then say why a for-each loop cannot do this job.

Plan. Going backwards means starting at the last valid index, a.length - 1, testing i >= 0, and decrementing. Use print rather than println so the values stay on one line, then close the line with a bare println().

Reverse.java

public class Reverse {
    public static void main(String args[]) {
        int[] a = {3, 1, 4, 1, 5};
        for (int i = a.length - 1; i >= 0; i--)
            System.out.print(a[i] + " ");
        System.out.println();
    }
}
5 1 4 1 3

Things to notice. The three parts of the loop header all flip together: start at the end, keep going while i has not passed the front, and step down. Getting one of the three right and the others wrong is how you end up with an infinite loop or an immediate exit.

A for-each loop always runs from index 0 forwards and gives you no index, so it simply cannot express "backwards". This is the clearest case of the key idea above: the shorter loop is not the more powerful one.

4.Arrays and methods

An array can be a parameter and it can be a return type. The type is written exactly as in a declaration — int[] for an array of int, String[] for an array of String — and the method title line follows the pattern from Lecture 2:

public static int sum(int[] data)              // takes an array, returns an int public static int[] copyOf(int[] data)         // takes an array, returns an array public static void shorten(String[] words)     // takes an array, returns nothing

Notice the third one. A method that returns void normally cannot affect the caller at all. With an array parameter it can, and that difference matters enough to demonstrate.

Worked Example— what a method can and cannot change

Two overloaded methods with the same name, one taking an int and one taking an int[]. Both set their parameter's contents to zero. Only one of them has any effect on main. Which?

PassArray.java

public class PassArray {
    public static void main(String args[]) {
        int[] a = {3, 1, 4};
        int n = 3;

        zeroOut(a);
        zeroOut(n);

        System.out.println("n is now " + n);
        System.out.print("a is now");
        for (int v : a) System.out.print(" " + v);
        System.out.println();
    }

    public static void zeroOut(int[] data) {
        for (int i = 0; i < data.length; i++) data[i] = 0;
    }

    public static void zeroOut(int x) {
        x = 0;
    }
}
n is now 3 a is now 0 0 0

n survives; a does not. The rule underneath is the same one that explained the for-each loop: a parameter is always a copy of the argument. What differs is what is being copied.

CallWhat gets copied into the parameterEffect on the caller
zeroOut(n)A copy of the number 3. x = 0 overwrites the copy.None. n is still 3.
zeroOut(a)A copy of the reference — of the arrow pointing at the array, not of the array's contents.data[i] = 0 follows the arrow to the one and only array and writes into it. main sees the change.

So a void method with an array parameter is a perfectly normal way to get work done in Java, and several of the exam problems at the bottom of this page depend on it. We will come back to references properly in Lecture 8, where the same idea explains a lot of object behavior.

One more thing worth noticing: this file has two methods called zeroOut. That is overloading, from Lecture 2 — Java picks the right one by looking at the type of the argument, and int and int[] are different enough that there is no ambiguity.

public static void print(int[] data) {
    if (data.length == 0) {
        System.out.println("(empty)");
        return;
    }
    for (int i = 0; i < data.length - 1; i++) System.out.print(data[i] + ", ");

}

5.Two-dimensional arrays

Definition— two-dimensional array

A two-dimensional array is written int[][] and is best understood as an array whose elements are themselves arrays. You create a rectangular one with new int[3][4] — three rows, each of length four — and you reach a single element with two indices, m[row][col].

m.length is the number of rows. m[i].length is the number of columns in row i. Because each row is a separate array, different rows may have different lengths; such an array is called irregular or jagged.

Worked Example— rows, columns, and irregular rows

Common Mistake— the wrong bound in the inner loop

This code is supposed to total a two-dimensional array. It compiles, it runs, it prints a number, and the number is wrong:

int[][] numbers = {
    {
        1, 2, 3, 4}
    , {
        0, 1, 2, 3}
}
;

The correct total is 16. The inner loop says col < numbers.length, which is the number of rows — 2 — so it only ever visits columns 0 and 1 and sums 1 + 2 + 0 + 1 = 4. The fix is one word:

for (int col = 0; col < numbers[row].length; col++) total += numbers[row][col];

6.Your first object: the Scanner class

Everything we have written so far has had its data baked into the source code. To read what a person types, Java gives you a class called Scanner — and using it means creating your first real object, so this is where the "object-oriented" part of the course title starts to show up.

Definition— class and object

Classes serve as blueprints for objects, packaging together some data and the methods that operate on it. An object is an instance of a class: one actual thing built to that blueprint, with its own copy of the data.

Scanner is the blueprint. new Scanner(System.in) builds one. If you build two of them, they are two separate objects with two separate sets of data, and what you do to one does not affect the other.

Lecture 7 is where we start writing our own classes. For now, Scanner is a good one to meet first, because you can describe it completely with the two lists every class has — its data and its methods.

7.Reading input, token by token and line by line

Definition— token

A token is a run of characters with no delimiter inside it. With the default delimiter — whitespace — a token is simply a "word": Ada, 212, 3.5.

next() and nextInt() are token methods. They skip over any leading whitespace, read one token, and stop. nextLine() is not a token method: it reads everything up to the end of the current line, spaces included, and consumes the newline.

In the sessions below, the input was typed at a real terminal, so each line you see repeated back after a prompt is what the user typed — the terminal echoes it. Everything else is what the program printed.

Worked Example— read a count, then read that many numbers

This is the standard shape of an input-driven array program, and you will write it many times: read the size first, allocate the array, then fill it in a loop. Note that nextInt() is perfectly happy to read several numbers from one typed line — whitespace is whitespace, and a newline is no different from a space.

ReadNumbers.java

import java.util.Scanner;

public class ReadNumbers {
    public static void main(String args[]) {
        Scanner input = new Scanner(System.in);

        System.out.print("How many numbers? ");
        int n = input.nextInt();

        int[] data = new int[n];
        System.out.print("Enter " + n + " numbers: ");
        for (int i = 0; i < n; i++) data[i] = input.nextInt();

        int total = 0;
        int largest = data[0];
        for (int i = 0; i < data.length; i++) {
            total += data[i];
            if (data[i] > largest) largest = data[i];
        }

        System.out.println("Sum:     " + total);
        System.out.println("Largest: " + largest);
        System.out.println("Average: " + total / (double) data.length);
        input.close();
    }
}

The user typed 4 and then 10 25 3 18. Work out the three result lines before revealing.

How many numbers? 4 Enter 4 numbers: 10 25 3 18 Sum:     56 Largest: 25 Average: 14.0

Four points about the structure, all of which show up in exam solutions.

  • new int[n] with a variable size. The size does not have to be a literal. This is the whole reason we read the count first.
  • System.out.print for prompts, not println. That leaves the cursor on the same line so the typed answer appears next to the question.
  • largest starts at data[0], not at 0. Starting at 0 would be wrong for an array of all-negative numbers. Starting at the first element is always safe — provided the array is not empty, which is the data.length == 0 question again.
  • total / (double) data.length. Without the cast, 56 / 4 is integer division. It gives 14 here rather than 14.0, and it would give 14 instead of 14.5 for a different set of numbers.

The same input read two different ways. The user typed Ada Byron Lovelace and then CSCI 212 rocks. Square brackets are printed around each result so you can see exactly where it starts and ends — look closely at the second one.

Common Mistake— nextInt() followed by nextLine()

This program is from the course code. It reads a name and an age, then asks the user to say something. It compiles, it runs, and it never lets the user say anything.

UserInput.java

import java.util.Scanner;

public class UserInput {
    public static void main(String args[]) {
        Scanner input = new Scanner(System.in);
        System.out.println("Enter your name and age:");
        String name = input.next();
        int age = input.nextInt();
        System.out.println("Hello " + name + ", you are "
                + age + " years old.");

        String msg = input.nextLine();
        System.out.println("You said:");
        System.out.println(msg);

Here is a real session. The user typed Xinying 20, and then typed Java is fine — or tried to:

Enter your name and age: Xinying 20 Hello Xinying, you are 20 years old. Say something: You said:

The program printed You said: and then a blank line, and it never waited for the second answer at all.

Why. nextInt() read the token 20 and stopped right after the 0. The newline the user pressed at the end of that line is still sitting in the input, unread. So when nextLine() runs, it does its job perfectly: it reads everything from the cursor to the end of the current line, and everything from there to the end of the line is nothing. It returns the empty string instantly, and the program races past the prompt.

The fix is one extra nextLine() whose result you throw away, to consume the leftover newline:

Worked Example— refusing to crash on bad input

The loop keeps asking until hasNextInt() says yes. The input.next() inside the loop is essential — it throws away the offending token. Without it, the bad token would still be there on the next pass and the loop would spin forever. The user typed seven, then 12.5, then 42.

SafeRead.java

import java.util.Scanner;

public class SafeRead {
    public static void main(String args[]) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter an integer: ");
        while (!input.hasNextInt()) {
            System.out.print("That is not an integer. Try again: ");
            input.next();
        }
        int n = input.nextInt();
        System.out.println("You entered " + n);
        input.close();
    }
}
Enter an integer: seven That is not an integer. Try again: 12.5 That is not an integer. Try again: 42 You entered 42

12.5 was rejected too, which is correct: hasNextInt() asks whether the token can be read as an int, and 12.5 cannot. There is a matching hasNextDouble() if that is what you want.

The general pattern — ask hasNextX() before you call nextX() — is worth carrying with you. Its other big use is stopping a reading loop when the input runs out, which is exactly how Lecture 5 reads a file: while (input.hasNext()).

Quick Check 3.12

Write a complete program Sentinel.java that reads integers typed by the user into an array until the user enters -1, then prints how many numbers were read and their sum. The -1 itself is not part of the data. Assume there will be no more than 100 numbers.

            count++;

Finally, note that arr[i] = ... writes into a slot of the array, so the change is visible in main. Had the method instead done String s = arr[i]; s = s.substring(0, 2); it would have changed a local variable and main would print the original strings — the same mistake as assigning to the for-each variable.

"At least one" is an or. The whole method is a single return:

private static boolean positive(int x, int y) {
    return x > 0 || y > 0;
}

Resist the urge to write if (x > 0 || y > 0) return true; else return false;. It is correct but it says the same thing twice — a comparison already is a boolean in Java.

(b) private static int rowSum(int[][] a)

The comment says the first row, so there is only one loop, and it runs across row 0. Its bound is a[0].length — the length of that row — not a.length, which is the number of rows:

private static int rowSum(int[][] a) {
    int sum = 0;
    for (int i = 0; i < a[0].length; i++) sum += a[0][i];
    return sum;
}

Because we only read, a for-each over the row is equally good and is the form used in the posted solution: for (int num : a[0]) sum += num;. That works because a[0] is itself an int[].

(c) private static int smallest(int[] b)

Start the running minimum at the first element, then compare against the rest:

private static int smallest(int[] b) {
    int min = b[0];
    for (int i = 1; i < b.length; i++) if (b[i] < min) min = b[i];
    return min;
}

Problem 4 — Words longer than average (from CSCI 212 Midterm — Summer 2026)

Write a complete Java program in Midterm1.java that asks the user to enter the number of words, then reads that many words. The program should print all words whose length is greater than the average word length, in the same order in which they were entered.

A sample run of this program, where the user typed 6 and then the six words:

Enter the number of words: 6 Enter 6 words: java exam inheritance class object code Average length: 5.666666666666667 Words longer than average: inheritance object

Plan. This is the ReadNumbers shape from §7 with String in place of int. Read the count with nextInt(), allocate a String[] of that size, and fill it with next() — one call per word, which is why the six words can all sit on one typed line.

Then two passes over the array. The first adds up words[i].length() to get the total number of characters; divide by words.length as a double to get the average. The second pass prints every word longer than that average. Two passes are necessary, not lazy: you cannot know whether the first word beats the average until you have seen the last one.

Midterm1.java

import java.util.Scanner;

public class Midterm1 {
    public static void main(String args[]) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter the number of words: ");
        int n = input.nextInt();

        String[] words = new String[n];
        System.out.print("Enter " + n + " words: ");
        for (int i = 0; i < n; i++) words[i] = input.next();

        int totalLength = 0;
        for (int i = 0; i < words.length; i++) totalLength += words[i].length();
        double average = totalLength / (double) words.length;
        System.out.println("Average length: " + average);

        System.out.print("Words longer than average:");
        for (int i = 0; i < words.length; i++)
            if (words[i].length() > average) System.out.print(" " + words[i]);
        System.out.println();

        input.close();
    }
}
Enter the number of words: 6 Enter 6 words: java exam inheritance class object code Average length: 5.666666666666667 Words longer than average: inheritance object

Things to notice. The lengths are 4, 4, 11, 5, 6 and 4, giving 34 characters over 6 words — an average of 5.666666666666667. Only inheritance (11) and object (6) beat it, and they print in the order they were entered because we walk the array forwards.

totalLength / (double) words.length is the load-bearing cast. Without it, 34 / 6 is the int 5, average becomes 5.0, and class — length 5 — is still excluded but the printed average is wrong. On a different word list the truncation would change which words are printed too.

Using next() rather than nextLine() for the words is what lets the user type them all on one line, separated by spaces: each next() takes one token. And because the program never calls nextLine() at all, the leftover newline after nextInt() causes no trouble here — it is just more whitespace for the next next() to skip.

Problem 5 — The random-number study (from Exam 1 Practice Problems)

Write a complete Java program to be used for a psychology study into random number choices by a human volunteer. Ask the user to repeatedly type 2-digit numbers. Read the user input and discard any number that is less than 10 or greater than 100, but keep track of numbers within this range. When the user enters the number 100 the experiment ends and the program prints a summary with one line of output for each of the numbers from 10 to 99 that was used, of the form:

User chose 10 for 2.1% of choices. User chose 12 for 0.7% of choices.

Plan. The trick here is to stop thinking of the array as a list of the numbers typed and start thinking of it as a set of counters indexed by the number itself. Make int[] counts = new int[100], and when the user types 37, do counts[37]++. Slots 0 through 9 are never used and that is fine — wasting ten int values buys you an array whose index is the number, so no searching is ever needed.

Keep a separate total of how many valid numbers were entered, because the percentage is counts[i] out of total, not out of the array length. Loop forever, break on 100, ignore anything outside 10 to 99. Then walk i from 10 to 99 and print only the slots with a nonzero count.

PsychologyStudy.java

import java.util.Scanner;

public class PsychologyStudy {
    public static void main(String args[]) {
        Scanner input = new Scanner(System.in);
        int[] counts = new int[100];
        int total = 0;

        System.out.println("Type 2 digit numbers. Enter 100 to end:");
        while (true) {
            int n = input.nextInt();
            if (n == 100) break;
            if (n >= 10 && n <= 99) {
                counts[n]++;
                total++;
            }
        }
        input.close();

        for (int i = 10; i < counts.length; i++) {
            if (counts[i] > 0) {
                double percent = counts[i] * 100.0 / total;
                System.out.printf("User chose %d for %.1f%% of choices.%n", i, percent);
            }
        }
    }
}

A session where the user typed 37 42 7 37 99 250 42 37 100:

Type 2 digit numbers. Enter 100 to end: 37 42 7 37 99 250 42 37 100 User chose 37 for 50.0% of choices. User chose 42 for 33.3% of choices. User chose 99 for 16.7% of choices.

Things to notice. 7 and 250 were both discarded, so total is 6, not 8. 37 appears three times out of six, which is 50.0%; 42 twice, 33.3%; 99 once, 16.7%. Had we divided by 8 every percentage would have been wrong, which is why the counter has to be incremented in the same if that records the value.

counts[n]++ with n coming straight from the user is only safe because the surrounding if has already checked that n is between 10 and 99. Delete that check and a user typing -5 gets you an ArrayIndexOutOfBoundsException. Whenever an index comes from outside your program, something must validate it.

System.out.printf works like C's printf: %d is an integer, %.1f a double to one decimal place, %% a literal percent sign, and %n a line break. println with string concatenation would also pass, but it would print 50.0 and 33.33333333333333 inconsistently.

Finally, the loop shape here is while (true) with a break, while Quick Check 3.12 used a priming read. Both are standard; use whichever makes the sentinel test read more naturally.

Lecture Summary
  • An array holds many values of one type under one name, indexed from 0 to length - 1. Declaring it and creating it are separate steps, and the brackets may sit after the type (int[] a) or after the name (int a[]).
  • The size is required when you allocate with new, except with an initializer list, which counts itself. Once created, the size is fixed — "growing" an array means building a new one and copying.
  • New arrays are filled with defaults: 0, 0.0, false, null.
  • a.length is a property and takes no parentheses. s.length() is a method and requires them. Mixing them up is a compile error, and it is on the exam.
  • Reading past the end throws ArrayIndexOutOfBoundsException, and the message names both the index you asked for and the length you actually had.
  • The for-each loop for (int v : a) is the clean way to read every element. Assigning to v changes nothing; to write into the array you need an index.
  • A method that takes an array parameter shares the caller's array, so a void method can change it — which is how shorten and setToFive work.
  • A two-dimensional array is an array of arrays: m.length counts rows, m[i].length counts the columns of row i, and rows may legally have different lengths.
  • Scanner is a class — a blueprint. new Scanner(System.in) builds an object from it with its own source and its own delimiter. Its methods are next, nextInt, nextLine, hasNext, hasNextInt, useDelimiter and close, and it needs import java.util.Scanner;.
  • next and nextInt read one token and stop before the newline; nextLine reads to the end of the line. That mismatch is the leftover-newline trap, and the cure is one extra input.nextLine();.
