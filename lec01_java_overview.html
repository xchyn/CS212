1.What Java is, and what makes it different

You already know how to program. In CSCI 111 you wrote variables, loops, decisions, arrays and functions in C++. Almost none of that knowledge is going to be thrown away this semester — a for loop in Java looks exactly like a for loop in C++. What changes is the world the code lives in.

Definition— Java

Java is a high-level, object-oriented programming language created by James Gosling at Sun Microsystems and released in 1995. It was designed around the principle "write once, run anywhere" (WORA): a Java program is compiled once, and the result runs unchanged on any machine that has a Java Virtual Machine.

Java is used for Android apps, desktop applications, web back-ends and large enterprise systems. It is one of the most widely deployed languages in the world, which is a large part of why it is the language of this course.

The WORA promise is the single most important design decision in Java, and everything else follows from it. To understand it you need one more term.

Definition— bytecode and the JVM

When you compile C++, the compiler produces machine code — instructions for one specific processor and one specific operating system. An executable built on a Mac will not run on Windows.

When you compile Java, the compiler produces bytecode instead: instructions for an imaginary computer. Bytecode is stored in a .class file. The Java Virtual Machine (JVM) is a program that reads bytecode and carries out those instructions on your real machine. There is a JVM for Windows, one for macOS, one for Linux, one for Android. They all read the same bytecode.

Key Idea

C++ says: compile it separately for every machine. Java says: compile it once, and ship a different JVM to every machine. Your .class file is the thing that travels; the JVM is the thing that already lives on the target computer.

Four more features of Java follow from that same design, and they are worth naming now because we will keep bumping into them:

  • Object-oriented. Java is thoroughly object-oriented. Apart from the eight primitive types we meet in §4, everything in Java is an object. There is no such thing as a free-floating function in Java — every method lives inside a class. That is why even "hello world" needs a class around it.
  • Simplicity. Java's syntax is deliberately modelled on C and C++, but the low-level facilities are gone: no pointer arithmetic, no manual delete, no header files, no preprocessor.
  • Automatic memory management. Java has a garbage collector. You create objects with new; you never free them. When nothing refers to an object any more, the collector reclaims it. The whole category of memory-leak bugs you had to worry about in C++ largely disappears.
  • Security. Because your code runs inside the JVM rather than directly on the hardware, the JVM can check what it is doing — array bounds, type safety, access permissions — and stop it.

Quick Check 1.1

Your friend compiles a Java program on a Windows laptop and emails you the .class file. You have a Mac. Will it run? What would the answer be if it had been a C++ program compiled to an .exe?

Plan. The question is really "what is inside the file, and who reads it?" Decide what each compiler produced, then decide whether your machine has something that can read it.

The Java case: yes, it runs. javac on Windows produced bytecode, not Windows machine code. Bytecode is instructions for the JVM, and your Mac has a macOS JVM. You type java ClassName and the macOS JVM reads exactly the same bytecode the Windows JVM would have read.

The C++ case: no, it does not run. The .exe contains machine code addressed to an x86 processor and Windows operating-system calls. Your Mac has no idea what to do with it. To run that program you would need the C++ source code and a compiler on your own machine.

Things to notice. The Java program is not magic — something platform-specific still had to be written. It is just that Oracle wrote it (the JVM), once per platform, instead of you writing it. Notice also what has to already be on your Mac: not the Java compiler, just the JVM. That is why a user who runs your program needs a Java runtime, while you as a developer need a Java development kit.

2.The shape of a Java program

In C++ you could write a function that belonged to nothing in particular. Java does not allow that. Every method must be inside a class, so the smallest legal Java program is still a class.

Definition— class, method, main

A class is a named container for data and methods. For the next few lectures we will use classes purely as a place to park our code; from Lecture 7 onward they become the centre of everything.

A method is Java's word for a function. The difference from C++ is not behaviour, it is location: a method always lives inside a class.

main is the method the JVM calls when you run a program. Its signature is fixed — if you get one word wrong, the program compiles but will not start.

Here is the template. Memorise it; you will type it several hundred times this semester.

Example.java

public class Example {
    public static void main(String args[]) {

    }
}

Read it word by word, because every word is doing a job:

WordWhat it means
publicVisible to code outside this class. The JVM is outside your class, so main must be public or the JVM cannot call it.
class ExampleDeclares a class named Example. The file must be named Example.java.
staticThe method belongs to the class itself, not to any object of the class. This matters because when the JVM starts there are no objects yet — it has nothing to call main on. We come back to static properly in Lecture 9.
voidmain returns nothing. (In C++ you wrote return 0;. Java does not want it.)
String args[]An array of the command-line arguments. You may ignore it for now, but it must be in the signature.
Common Mistake

String args[] and String[] args mean exactly the same thing, and both are legal. What is not optional is the parameter itself. If you write public static void main() the program will compile perfectly and then refuse to run, because the JVM looks for a main that takes a String array and finds none. A compile that succeeds is not proof that the program starts.

Now the smallest useful program. This is the Java translation of the first C++ program you ever wrote.

3.Compiling and running

In C++ there was one step you cared about: turn source into an executable, then run the executable. Java splits this differently, and the two commands have confusingly similar names.

Procedure— from source file to output
  1. Save your source in a file whose name matches the public class exactly, including capitalisation: class Example1 goes in Example1.java.
  2. Compile. Run javac Example1.java. If it succeeds it prints nothing at all and creates Example1.class. Silence means success.
  3. Run. Run java Example1. Note carefully: the class name, with no .java and no .class extension. You are telling the JVM which class to look for, not which file to open.

Common Mistake— the file name must match the class name

This is the single most common first-week error, and the compiler is unusually helpful about it. Save a class called Greeting in a file called Hello.java and javac Hello.java answers:

Hello.java:1: error: class Greeting is public, should be declared in a file named Greeting.java
public class Greeting {
       ^
1 error

The rule applies to public classes, and it is case-sensitive: example1.java will not do for class Example1. Read the message — it tells you the exact file name it wants.

You will see a lot of javac messages this semester, so start reading them properly now. Every one has the same four parts: the file and line number, the word error, a description, and a caret ^ pointing at the offending column. Here is the most common one of all:

Semi.java:3: error: ';' expected

Quick Check 1.3

You have written a class called Average and saved it as Average.java.

(a) You type javac Average.java and nothing at all is printed. Did it work?

Plan. Ask what the compiler prints on success versus on failure.

Yes, it worked. javac is silent on success; the only evidence is the new file Average.class sitting next to your source. If there had been a problem you would have seen at least one error: line and a count.

Things to notice. This unnerves people coming from environments that say "Build succeeded". Get used to checking for the .class file, or just move straight on to running it.

(b) You then type java Average.java. What is wrong with that command?

Plan. Recall what the argument to java denotes.

The argument to java is a class name, not a file name, so the correct command is java Average. Writing java Average.java asks the JVM to find a class literally named java inside a package called Average.

Things to notice. Modern JDKs will actually accept java Average.java — single-file source mode compiles and runs in one step. That is convenient but it is not what we are doing here, and it will confuse you when you move to a project with more than one file. Learn the two-step version: javac Average.java then java Average.

4.The eight primitive types

Definition— primitive type

A primitive type is one of eight built-in types that hold a plain value directly, rather than a reference to an object. They are the only things in Java that are not objects, and their names are all lowercase — that lowercase is how you spot a primitive at a glance.

They come in four families: whole numbers, decimals, a single character, and a truth value.

TypeFamilySizeRange or values
byteinteger8 bits−128 to 127
shortinteger16 bits−32,768 to 32,767
intinteger32 bits−2,147,483,648 to 2,147,483,647
longinteger64 bitsabout ±9.2 × 1018
floatdecimal32 bitsabout 7 significant digits
doubledecimal64 bitsabout 15 significant digits
charcharacter16 bitsone Unicode character, written in single quotes: 'J'
booleantruth value—true or false only

Two differences from C++ are worth flagging immediately.

  • The sizes are fixed. In C++, int is "whatever is natural on this machine". In Java an int is always 32 bits, on every platform. That is part of the WORA promise: arithmetic must give the same answer everywhere.
  • boolean is not a number. In C++ you could write if (n) and rely on nonzero meaning true. Java refuses. A condition must be an actual boolean.
Worked Example— all eight, and their limits

Each primitive type has a matching wrapper class that carries useful constants; Integer.MAX_VALUE is the largest value an int can hold. Notice the L suffix on the long literal and the f suffix on the float literal — without them Java reads 9000000000 as an int (too big) and 3.14 as a double (too wide).

Quick Check 1.5

Choose the most appropriate primitive type for each of the following, and say why.

(a) A student's age in whole years.

int. A byte would technically fit any human age (max 127) but there is nothing to gain: you are not storing millions of them, and using byte invites arithmetic surprises. int is the default choice for whole numbers in Java, and you should need a reason to pick anything else.

(b) A GPA such as 3.47.

double. It has a fractional part, so it must be float or double, and double is Java's default for decimals — an unadorned literal like 3.47 is a double. Choosing float means writing 3.47f everywhere and getting roughly seven digits of precision instead of fifteen, for no benefit.

(c) Whether a student has submitted an assignment.

boolean. It has exactly two states. Resist the C habit of using an int that is 0 or 1; Java will not let you use that int as a condition anyway.

(d) A student's letter grade, one of A, B, C, D, F.

char, written with single quotes: char grade = 'A';. Double quotes would make it a String, which is a whole different kind of thing — an object, not a primitive — and we take that up in Lecture 4.

Things to notice across all four parts. The question "which type?" is really two questions: what shape is the data (whole? fractional? one character? yes/no?), and only then, how big does it need to be. Answer them in that order and you will almost always land on int, double, char or boolean — which is exactly as it should be. byte, short, float and long exist for specific reasons (memory-constrained arrays, values beyond two billion) that you will rarely hit in this course.

5.Arithmetic, and the division trap

The operators are the ones you already know: +, -, *, /, %, and the shorthands +=, -=, ++, --. There is one rule about / that causes more wrong answers on exams than anything else in the first month.

Key Idea— the type of the operands decides the operation

If both operands of / are integers, Java performs integer division: it divides and throws the remainder away. If either operand is a double, Java performs real division. The type of the result is decided by the operands, never by what you are about to assign it to.

Common Mistake— averaging integers

The classic version of this bug is an average:

int a = 90, b = 85, c = 78;
double average = (a + b + c) / 3;      // WRONG: prints 84.0

Declaring average as a double changes nothing. By the time the assignment happens, (a + b + c) / 3 has already been computed as the int 84. The fix is to make one operand a double inside the expression:

double average = (a + b + c) / 3.0;    // right: 84.33333333333333

Writing 3.0 instead of 3 is the smallest possible fix, and it is the one to reach for. (double) (a + b + c) / 3 also works.

Quick Check 1.6

Give the exact value and the type of each expression.

(a) 17 / 5

3, an int. Both operands are integers, so the 0.4 is discarded.

(b) 17 % 5

(c) 17 / 5.0

Things to notice. Parts (c) and (d) are the whole lesson: the cast has to be applied to an operand, not to the finished result. When you see a cast in someone's code, look immediately at what is inside its parentheses.

6.Printing, and what + really does

In C++ you chained values onto cout with <<. Java has no such operator for output. Instead you build one String and hand it to println, and you build it with +.

Definition— string concatenation

The + operator is overloaded. If both operands are numbers it adds them. If either operand is a String, it converts the other one to text and joins them — this is called concatenation. And + evaluates strictly left to right.

Those two facts together — overloaded meaning, left-to-right order — produce results that look wrong until you trace them one step at a time.

Worked Example— six uses of one operator

Predict all six lines. At least one of them will surprise you.

Let int x = 5, y = 3;. Give the exact output of each statement.

7.Loops and decisions

This is the shortest section in the lecture, and that is the point: for, while, do-while, if, else and switch are written in Java exactly as you wrote them in C++. The braces, the semicolons in the for header, the else if chain — all identical.

Common Mistake— the one real difference

A Java condition must be a boolean. Two C++ habits stop working:

  • if (n) meaning "if n is nonzero" — not legal in Java. Write if (n != 0).
  • if (n = 5) — the classic typo for ==. In C++ this compiles and is always true. In Java the compiler catches it, because n = 5 produces an int and an int is not a boolean:
Asg.java:4: error: incompatible types: int cannot be converted to boolean
        if (n = 5) System.out.println("five");
              ^
1 error

This is a small example of a large theme: Java's type system is deliberately stricter than C++'s, and the payoff is that a whole class of bugs becomes a compile error instead of a wrong answer at 2am.

Worked Example— the harmonic sum, ported from CSCI 111

This is the C++ program from your CSCI 111 notes, alongside its Java translation. It exercises division, a for loop, a while loop and an if/else, so it is a complete tour of the lecture in one file.

C++ (CSCI 111) — for comparison only

#include <iostream>
using namespace std;
int main() {
    cout << "7 / 3 = " << 7/3 << endl;
    cout << "7.0 / 3 = " << 7.0/3 << endl;
    double sum = 0.0;
    for (int i = 1; i <= 100; i++) sum += 1.0 / i;
    cout << "The sum of first 100 reciprocals is: " << sum << endl;
    int n = 101;
    while (sum < 10) {
        sum += 1.0 / n;
        n++;
    }
    cout << "We need " << n << " reciprocals to get a sum of 10" << endl;
    if (n % 2 == 0) cout << n << " is even." << endl;
    else cout << n << " is odd." << endl;
    return 0;
}

Example2.java

public class Example2 {
    public static void main(String args[]) {
        System.out.println("7 / 3 = " + 7/3);
        System.out.println("7.0 / 3 = " + 7.0/3);

        double sum = 0.0;
        for (int i = 1; i <= 100; i++)
            sum += 1.0 / i;
        System.out.println("The sum of first 100 reciprocals is: " + sum);

        int n = 101;
        while (sum < 10) {
            sum += 1.0 / n;
            n++;
        }
        System.out.println("We need " + n + " reciprocals to get a sum of 10");
        if (n % 2 == 0) System.out.println(n + " is even.");
        else System.out.println(n + " is odd.");
    }
}

Two questions before you reveal. First: is the second line going to print 2.33 or something longer? Second: roughly how big will n be?

7 / 3 = 2
7.0 / 3 = 2.3333333333333335
The sum of first 100 reciprocals is: 5.187377517639621
We need 12368 reciprocals to get a sum of 10
12368 is even.

Three things worth pulling out.

  • sum += 1.0 / i, not 1 / i. If that had been 1 / i, then for every i greater than 1 integer division would give 0, and the sum would come out as a flat 1.0. Writing the numerator as 1.0 is the entire difference between a correct program and a silently wrong one.
  • The harmonic series grows brutally slowly. One hundred terms only reach about 5.19. Getting to 10 takes 12,368 terms — more than a hundred times as many for less than double the sum. That is the logarithm at work.
  • n is 12368 when the loop stops, and 12368 is even, so the if takes the first branch. Note that the loop increments n after adding, so at exit n is one past the last term used — a classic off-by-one worth being deliberate about.
Quick Check 1.9

What does this print? Be careful with the second loop.

public class LoopDemo {
    public static void main(String args[]) {
        for (int i = 1; i <= 5; i++) System.out.print(i * i + " ");
        System.out.println();

        int n = 1;
        while (n < 100) n = n * 3;
        System.out.println("First power of 3 at least 100: " + n);

        int count = 0;
        for (int i = 1; i <= 30; i++) {
            if (i % 3 == 0 && i % 5 == 0) count++;
        }
        System.out.println("Multiples of 15 up to 30: " + count);
    }
}

Plan. Take the three pieces separately. The for loop prints five squares on one line. The while loop multiplies by 3 until the value reaches 100 — run the powers: 1, 3, 9, 27, 81, 243. It exits the first time the condition fails, so the answer is the first power of 3 that is not less than 100. The counting loop needs i divisible by both 3 and 5, which means divisible by 15.

1 4 9 16 25
First power of 3 at least 100: 243
Multiples of 15 up to 30: 2

Things to notice. 81 is less than 100, so the loop body runs once more and jumps to 243 — it overshoots, and that is correct behaviour for while (n < 100). If you wanted the last power below 100 you would have to remember the previous value.

In the first line, i * i + " " works because * binds tighter than +, so the square is computed before the space is concatenated. Had you written "" + i * i it would still be fine, but i + i + " " would print the double, not the square.

The multiples are 15 and 30, so count is 2. Java's && short-circuits exactly as C++'s does: if i % 3 == 0 is false, i % 5 == 0 is never evaluated.

Quick Check 1.10

Adapt the harmonic-sum program. Write Harmonic.java that finds how many terms of 1 + 1/2 + 1/3 + … are needed before the sum first exceeds 5, and prints both the number of terms and the sum at that moment. Start the count at zero rather than hard-coding 100 terms first.

Plan. A while loop is right here because we do not know in advance how many iterations we need — that is the thing we are trying to find out. Keep two variables: the running sum and the number of terms used so far. Loop while the sum has not yet passed 5. Increment terms before adding 1.0 / terms, so the divisor is never zero and terms ends up holding exactly the number of terms added.

Harmonic.java

public class Harmonic {
    public static void main(String args[]) {
        double sum = 0.0;
        int terms = 0;

        while (sum <= 5.0) {
            terms++;
            sum += 1.0 / terms;
        }

        System.out.println("Terms needed: " + terms);
        System.out.println("Sum is now:   " + sum);
    }
}
Terms needed: 83
Sum is now:   5.002068272680166

Things to notice. The order inside the loop matters. Incrementing first means terms counts the term just added, so no adjustment is needed after the loop. Had you written sum += 1.0 / terms; terms++; you would divide by zero on the first pass — and because these are double values, Java would not even throw an error: 1.0 / 0 is Infinity, and the loop would exit immediately with a nonsense answer. Integer division by zero throws an exception; floating-point division by zero does not. That difference will catch you again in Lecture 20.

Choosing sum <= 5.0 rather than sum < 5.0 matters only in the unlikely event the sum lands exactly on 5. Using while (sum < 5.0) here gives the same 83 terms.

Quick Check 1.11

Each of these three lines has a problem. Say what the compiler will tell you, or if it compiles, what goes wrong at run time.

(a) int n = 3.5;

A compile error. 3.5 is a double, and squeezing a double into an int would throw away the fractional part, so Java refuses to do it silently:

Lossy.java:3: error: incompatible types: possible lossy conversion from double to int
        int n = 3.5;
                ^
1 error

If you genuinely want the truncation, say so with a cast: int n = (int) 3.5; gives 3.

(b) if (count = 5) System.out.println("five");

A compile error, and a welcome one. count = 5 is an assignment whose value is the int 5, and Java will not treat an int as a condition:

Asg.java:4: error: incompatible types: int cannot be converted to boolean
        if (n = 5) System.out.println("five");
              ^
1 error

The author meant ==. In C++ this same typo compiles cleanly, always takes the if branch, and quietly overwrites count.

(c) double half = 1 / 2;

This one compiles. That is exactly why it is dangerous. 1 / 2 is integer division giving 0, and widening the int 0 to a double is perfectly legal, so half becomes 0.0. There is no warning and no error — just a wrong answer.

Write 1 / 2.0, or 1.0 / 2.

Things to notice across all three parts. Two of these three the compiler catches for you; the third it does not. That is the shape of most real debugging. When a number comes out as 0 or 0.0 and you cannot see why, look for an integer division you did not intend — it is the first thing to check, every time.

Problem 1 — What is the output?

Consider the following Java program.

Output1.java

public class Output1 {

        int a = 9, b = 4;
        double x = 9;
        char g = 'B';

        System.out.println(a / b);              // line (a)
        System.out.println(a % b);              // line (b)
        System.out.println(x / b);              // line (c)
        System.out.println(a / (double) b);     // line (d)
        System.out.println((double) (a / b));   // line (e)
        System.out.println("a/b = " + a / b);   // line (f)
        System.out.println("a/b = " + a + b);   // line (g)
        System.out.println(g + 1);              // line (h)
        System.out.println("" + g + 1);         // line (i)

        int n = 0, s = 0;
        while (s < 10) { n++; s += n; }
        System.out.println(n + " " + s);        // line (j)
    }
}

(a) What is the output at line (a)?

2. Both a and b are int, so integer division: 9 ÷ 4 = 2 remainder 1.

(b) What is the output at line (b)?

1. The remainder that line (a) discarded.

(c) What is the output at line (c)?

2.25. x is a double, so b is promoted and real division happens. 9.0 ÷ 4 is exactly 2.25 — a quarter is representable in binary, so there is no trailing noise here.

(d) What is the output at line (d)?

2.25. The cast applies to b alone, so this is 9 ÷ 4.0.

(e) What is the output at line (e)?

2.0. The parentheses make a / b an integer division that yields 2; the cast then widens 2 to 2.0. Compare this line with (d) — same symbols, different parentheses, different answer.

(f) What is the output at line (f)?

a/b = 2. / binds tighter than +, so a / b is computed as the int 2 first, and only then concatenated.

(g) What is the output at line (g)?

a/b = 94. There is no arithmetic here at all. Left to right: "a/b = " + a is already a String, so + b just appends the character 4 after the character 9.

(h) What is the output at line (h)?

67. No String is involved, and a char is a number: 'B' is 66, so 'B' + 1 is 67. Java prints it as a number because the type of the expression is int, not char.

(i) What is the output at line (i)?

B1. The empty String at the front turns the first + into a concatenation, so 'B' is converted to text as the character B, and then 1 is appended.

(j) What is the output at line (j)?

4 10. Trace the loop: it accumulates 1, 3, 6, 10 into s while n goes 1, 2, 3, 4. After s becomes 10 the condition s < 10 is false and the loop stops, leaving n at 4.

On an exam these pairs are worth a point each and cost nothing but care. Build the habit of annotating the type of each subexpression as you read: writing a small int or String above each + turns this from a memory exercise into bookkeeping.

Problem 2 — Write a complete program

Write a complete Java program in Squares.java that prints the squares of the integers 1 through 10 on a single line separated by spaces, and then, on separate lines, their total and their average. The average must be printed as a decimal.

A sample output of this program:

1 4 9 16 25 36 49 64 81 100
Total:   385
Average: 38.5

Plan. One for loop does both jobs: print each square with print (not println, so they stay on one line) and accumulate into a running total. After the loop, a bare println() closes the line. The total is a genuine int, so keep it as one. The average is a total divided by 10 and must not be integer division — write 10.0.

Squares.java

public class Squares {
    public static void main(String args[]) {
        int total = 0;
        for (int i = 1; i <= 10; i++) {
            System.out.print(i * i + " ");
            total += i * i;
        }
        System.out.println();
        System.out.println("Total:   " + total);
        System.out.println("Average: " + total / 10.0);
    }
}
1 4 9 16 25 36 49 64 81 100
Total:   385
Average: 38.5

Things to notice. There is a trailing space after 100 because every square is followed by " ". That matches the sample output, but if you wanted to avoid it you would print the separator before every square except the first.

total / 10.0 gives 38.5 exactly. Had you written total / 10 you would have got 38 — and because 385 / 10 is 38.5, this is a case where the truncation loses a visible half-point rather than a rounding error you might not notice.

Computing i * i twice is slightly wasteful; a local int sq = i * i; inside the loop would be cleaner. At this scale it makes no measurable difference, but the habit of naming a value you use more than once is worth forming now.

public class Grades {

Problem 4 — Translate from CSCI 111

Below is a C++ program of the kind you wrote in CSCI 111. Write the equivalent complete Java program in Countdown.java. It must produce the same output.

C++ (CSCI 111) — translate this

#include <iostream>
using namespace std;
int main() {
    int n = 5;
    while (n > 0) {
        cout << n << "... ";
        n--;
    }
    cout << "liftoff!" << endl;
    int evens = 0;
    for (int i = 1; i <= 20; i++)
        if (i % 2 == 0) evens++;
    cout << "Even numbers from 1 to 20: " << evens << endl;
    cout << "Half of them is " << evens / 2.0 << endl;
    return 0;
}

Plan. Work through the differences mechanically rather than rewriting from scratch. Drop #include and using namespace. Wrap everything in a public class Countdown whose file is Countdown.java. Turn int main() into public static void main(String args[]) and delete return 0;. Replace every cout << ... << endl with a println whose argument is a single String built with +, and every cout << without endl with a print. The loops, the if, and the arithmetic transfer unchanged.

Countdown.java

public class Countdown {
    public static void main(String args[]) {
        int n = 5;
        while (n > 0) {
            System.out.print(n + "... ");
            n--;
        }
        System.out.println("liftoff!");

        int evens = 0;
        for (int i = 1; i <= 20; i++)
            if (i % 2 == 0) evens++;
        System.out.println("Even numbers from 1 to 20: " + evens);
        System.out.println("Half of them is " + evens / 2.0);
    }
}
5... 4... 3... 2... 1... liftoff!
Even numbers from 1 to 20: 10
Half of them is 5.0

Things to notice. System.out.print(n + "... ") is the direct translation of cout << n << "... ", and it works because n is joined to a String. If you had written two separate calls, print(n) then print("... "), the output would be identical — either is fine.

The last line is the one to be careful with. evens / 2.0 prints 5.0; evens / 2 would print 5. Both are arithmetically right here because 10 is even, but the types differ, and the C++ original prints 5 because cout drops the trailing .0 on a whole double. This is a genuine difference in output formatting between the two languages, not a translation error — Java always shows a double with a decimal point.

Notice too that the for loop body is a bare if with no braces, which is legal in both languages. It is also how single-statement bodies get accidentally broken when someone adds a second line later. Bracing every loop body is a habit worth having.

Lecture Summary
  • Java compiles to bytecode, not machine code. The JVM reads bytecode, and that is what makes one compiled program run everywhere.
  • Everything lives in a class. The skeleton is public class Name { public static void main(String args[]) { } }, and the file must be called Name.java.
  • Two commands, not one: javac Name.java compiles (silence means success), java Name runs. The second takes a class name, not a file name.
  • Eight primitive types. Default to int, double, char, boolean unless you have a reason not to. Sizes are fixed on every platform.
  • If both operands of / are integers you get integer division. Fix it by making one operand a double — inside the expression, not at the assignment.
  • + means addition until the first String appears, and concatenation from then on. Parenthesise the arithmetic you actually want.
  • Loops and decisions are exactly as in C++, except that a condition must be a real boolean — which is why Java catches if (n = 5) and C++ does not.
