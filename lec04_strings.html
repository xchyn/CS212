Text in Java is an object, not a primitive — and almost everything that surprises you about strings follows from that one fact.

1.A String is an object

Last time we read input with Scanner — next(), nextInt(), nextLine() — and stored the results in arrays. Almost everything Scanner handed back was a String, and we used it without asking what it was. Today we ask.

Look at the eight primitive types from Lecture 1: byte, short, int, long, float, double, char, boolean. String is not on that list. Every one of the primitives is written in lowercase; String has a capital S. That capital letter is not decoration — it is telling you that String is a class, and that every piece of text you handle this semester is an object of that class.

Definition— the String class

The String class in Java is the fundamental component for handling text data. A String represents an immutable sequence of characters, and it provides a large number of methods for manipulating and analyzing text.

Two words in that sentence are doing all the work. Sequence of characters means a string has a length and its characters have positions, numbered from 0, exactly like an array. Immutable means that once a String object exists, the characters inside it can never be changed — a promise we unpack in §4.

The consequence you must absorb today is what a String variable holds.

Key Idea— a String variable holds a reference

An int variable holds a number. A String variable does not hold text — it holds a reference: the address of a String object that lives somewhere else in memory.

So a String variable is more like a luggage tag than a suitcase. Two different tags can name the same suitcase, and two identical-looking suitcases can sit side by side with different tags. Every puzzle in this lecture is a question about tags versus suitcases.

Because String is a class, you call methods on a string with a dot, the same way you called scanner.nextInt(). Here is the program from your instructor's notes that does nothing but exercise a handful of them.

Quick Check 4.1

Both of these compile. What is different about the two variables, and why does only one of them have methods you can call with a dot?

char  initial = 'X';
String name   = "Xinying";

Plan. Ask the same two questions of each declaration: is the type primitive or a class, and therefore does the variable hold a value or a reference?

char is one of the eight primitive types. initial holds one 16-bit value — the Unicode code point for X — directly, in the variable itself. Primitives have no methods, so initial.length() is not a thing you can write; there is no object there to ask.

String is a class. name holds a reference to a String object that lives elsewhere in memory, and that object carries all of the String methods with it. So name.length() is legal and gives 7.

Things to notice. The single quotes versus double quotes are how Java tells the two apart in your source code: 'X' is a char literal, "X" is a String literal — a one-character string, and a completely different type. Getting this backwards produces the error incompatible types: String cannot be converted to char, which reads like nonsense until you notice the quotes.

2.Two ways to create a string, and the string pool

Strings can be created in two ways, and the difference between them is the single most heavily tested idea in this lecture.

Definition— the two ways to make a String

Using a string literal. You write the text in double quotes and Java makes the object for you:

String str1 = "Hello, World!";

Using the new keyword. You ask explicitly for a brand-new object, exactly as you would with any other class:

String str2 = new String("Hello, World!");

Both variables end up referring to a String object whose characters are Hello, World!. They are not, however, referring to the same object.

Definition— the string pool

The string pool (also called the string constant pool) is a region of memory the JVM reserves for string literals. When your program uses the literal "Hello, World!", the JVM first looks in the pool. If an object with exactly those characters is already there, it reuses it. If not, it creates one and puts it in the pool.

Because strings are immutable, sharing one object between many variables is completely safe — nobody can modify it out from under anybody else. That safety is precisely what makes the pool possible, and it is why Java bothers.

new String(...) opts out of all of this. new means make me a new object, and Java takes you at your word: the result is a fresh object outside the pool, even if an identical string is sitting in the pool already.

Here is the picture your instructor draws on the board, and it is worth copying into your own notes. Three declarations:

String str1 = "Hello, World!";
String str2 = new String("Hello, World!");
String str3 = "Hello, World!";

Two arrows point at one pooled object; one arrow points at an object of its own. Three variables, but only two objects. Hold that picture — the next section is nothing but consequences of it.

3.Comparing strings: == versus .equals

This is the central idea of the lecture. If you take one thing away from today, take this.

Key Idea— == compares tags, .equals compares contents

For two String variables x and y:

  • x == y asks are these the same object? It compares the two references — the addresses — and nothing else.
  • x.equals(y) asks do these two objects hold the same characters? It compares the text, character by character.

When you want to know whether two strings say the same thing, you want .equals. Essentially always.

== still means exactly what it meant in Lecture 1: compare the two values sitting in the two variables. It is just that for a String the value sitting in the variable is a reference, not text. Nothing about == changed; what changed is what is in the box.

Worked Example— the string pool, measured

This program takes the three declarations from §2 and asks all six possible questions about them. Write down your six answers before you reveal — and be ready to explain why str1 and str3 behave differently from str2.

Notice how badly == misleads here. It reports true in one case and false in two others for three variables that all say the same thing. If you had used == to decide whether the user typed the right answer, your program would be right or wrong depending on something you never wrote down and cannot see — whether the string happened to come from a literal.

Also notice the parentheses in ("str1 == str2 : " + (str1 == str2)). They are required. Without them, + would bind tighter than == and Java would try to compare a String against a String after concatenating, which does not mean what you want and in most arrangements will not even compile.

Common Mistake— comparing user input with ==

This is the bug that gets written most often, and the one that hurts most, because it tends to work in tiny test programs and then fail on real input. Strings that Scanner builds at run time are not pooled: they are fresh objects, so == against a literal is false no matter what the user typed.

Definition— equals, equalsIgnoreCase, compareTo

The String class offers three comparison methods.

  • x.equals(y) returns a boolean: true when the two strings hold exactly the same characters, including case.
  • x.equalsIgnoreCase(y) returns a boolean too, but treats upper and lower case as the same. "Java".equalsIgnoreCase("JAVA") is true.
  • x.compareTo(y) returns an int, not a boolean, and it tells you the order: negative if x comes before y, zero if they are equal, positive if x comes after y.

The ordering compareTo uses is dictionary order over Unicode code points, so all the capital letters (A is 65) come before all the lowercase letters (a is 97). It is not the ordering a librarian would use.

4.Immutability

Definition— immutable

An object is immutable when its contents can never change after it is created. Every String object in Java is immutable.

So there is no String method that edits a string. Every method that looks like it modifies one — toUpperCase, trim, replace, substring, concat — actually leaves the original object untouched and returns a brand-new String.

Key Idea— if you do not catch the result, it is gone

s.toUpperCase(); on a line by itself is a legal statement that accomplishes precisely nothing. It builds an uppercase copy of s and then throws it away, because nothing was assigned. What you meant was s = s.toUpperCase();

Worked Example— the difference one = makes

The same method is called three times in three different ways. Predict what s is at each stage.

Read that last row carefully, because the wording matters. s = s.toUpperCase() did not change the string hello into HELLO. The object holding hello is still out there, unchanged, exactly as immutability promises. What changed is which object s points at. You moved the luggage tag; you did not repack the suitcase.

The same is true of +. t + " 212" cannot append to t — it builds a third String from the characters of the other two. This is why building a long string by repeatedly using += inside a loop is slow: each pass creates a whole new object. For the sizes in this course you will never notice, but it is the reason StringBuilder exists.

public class CleanFixed {

        System.out.println("[" + raw + "]");

Things to notice. You can also chain the calls into one statement: raw = raw.trim().toUpperCase();. That works because raw.trim() is a String, so you can immediately call another String method on it. Chaining reads left to right in the order the operations happen, and it avoids the temptation to write a call whose result goes nowhere.

The square brackets in the println are a debugging habit worth stealing. Printing [ + s + ] makes leading and trailing spaces visible; printing s on its own hides them, and hidden spaces are the reason a comparison you are certain about keeps coming out false.

5.Looking at characters: length, charAt, isEmpty

Definition— string information and character access
  • s.length() returns an int: how many characters s has. Note the parentheses — for an array it was a.length with no parentheses, for a string it is s.length() with them. Java will not let you mix them up, but you will try.
  • s.isEmpty() returns true exactly when s.length() is 0, that is, when s is the empty string "".
  • s.charAt(i) returns the char at position i. Positions run from 0 to s.length() - 1.
Worked Example— walking a string one character at a time

length() and charAt together let you write the string equivalent of a for loop over an array — and that loop is the backbone of almost every string exercise on the exam. Watch position 4 in particular.

s.charAt(4) is the space between CSCI and 212, which is why it is printed inside brackets — on its own it would be invisible. A space is a character with a position, a code point (32) and a place in the length. Forgetting that is the reason people miscount indexOf results all semester.

Memorize this loop header; you will write it dozens of times:

for (int i = 0; i < s.length(); i++) {
    char c = s.charAt(i);
    // ... do something with c ...
}

The last character is at s.length() - 1, never at s.length(). That is exactly the array convention from Lecture 3, and the condition i < s.length() — strictly less than — is what keeps you inside the string.

Common Mistake— reading past the end

"CSCI".charAt(4) compiles perfectly. There is no way for the compiler to know that 4 is too big. At run time the program stops:

Exception in thread "main" java.lang.StringIndexOutOfBoundsException: Index 4 out of bounds for length 4
	at java.base/java.lang.String.charAt(String.java:1544)
	at OffEnd.main(OffEnd.java:4)

(The middle of the stack trace, which lists the JDK's own internal methods, is left out here.) Read the message: index 4, length 4. The valid positions are 0, 1, 2 and 3. Writing i <= s.length() in a loop header produces exactly this, on the very last iteration, after the loop has otherwise worked perfectly — which is why it is so easy to miss when you test with one short input.

6.Cutting and searching: substring, indexOf, contains

Definition— substring

substring comes in two forms, and the difference is worth stating precisely.

  • s.substring(begin) returns everything from position begin to the end of s.
  • s.substring(begin, end) returns the characters from position begin up to but not including position end.

That half-open convention is the thing to internalize: the length of the result is always end - begin, and s.substring(0, s.length()) is the whole string. begin may equal s.length(), in which case you get the empty string rather than an error.

Definition— searching a string
  • s.indexOf(t) returns the position of the first occurrence of t in s, or -1 if t does not occur at all.
  • s.lastIndexOf(t) returns the position of the last occurrence, or -1.
  • s.indexOf(t, from) starts looking at position from instead of at 0. lastIndexOf takes the same second argument, and searches backwards from it.
  • s.contains(t) returns a boolean: true when t occurs anywhere in s. It is exactly s.indexOf(t) != -1, written more readably.

All of these are case-sensitive, and all of them accept either a String or a single char.

7.Building new strings: trim, replace, case, split

Definition— string manipulation and conversion
  • s.toUpperCase() and s.toLowerCase() return a new string with every letter converted. Non-letters are left alone.
  • s.trim() returns a new string with whitespace removed from both ends. The interior is untouched.
  • s.replace(oldChar, newChar) returns a new string with every occurrence of one character replaced by another. There is also a version taking two String arguments, s.replace("World", "CSCI 212"), which replaces every occurrence of a whole substring.
  • s.concat(t) returns s followed by t. It does exactly what s + t does; the + form is what you will normally write.
  • s.split(regex) returns a String array of the pieces of s between occurrences of the separator.
  • String.valueOf(x) converts any primitive x into its text form. Note that this one is called on the class, not on a string object.

Every one of these returns a new String. None of them changes s.

Worked Example— split, and why the separator matters

split is how you get from a line of text to the individual words in it, and it is the method your instructor's file-processing programs lean on hardest. The argument is a pattern, not a plain string: "\\s" is the pattern meaning "one whitespace character". The second argument, -1, tells Java to keep empty pieces rather than dropping the ones at the end.

Before you reveal: how many pieces does "one two" split into, when the separator is one space and there are three spaces?

SplitDemo.java

public class SplitDemo {
    public static void main(String args[]) {
        String line = "CSCI 212 is easy";
        String words[] = line.split("\\s", -1);

        System.out.println("number of words: " + words.length);
        for (int i = 0; i < words.length; i++) {
            System.out.println(i + " -> [" + words[i] + "]");
        }

        String csv = "Ann,Bob,,Dee";
        String parts[] = csv.split(",", -1);
        System.out.println("parts: " + parts.length);
        for (int i = 0; i < parts.length; i++) {
            System.out.println(i + " -> [" + parts[i] + "]");
        }

        String spaced = "one   two";
        System.out.println("one   two split on \\s  gives " + spaced.split("\\s", -1).length);
        System.out.println("one   two split on \\s+ gives " + spaced.split("\\s+", -1).length);
    }
}

Three things to take from this.

  • split returns an array, so everything you know about arrays applies: words.length (no parentheses — it is an array, not a string) and words[i] to reach an element.
  • Consecutive separators produce empty pieces. Ann,Bob,,Dee has four fields, one of which is empty, and that is usually what you want for comma-separated data. But "one two" with three spaces splits into four pieces — one, two empty strings, and two. The pattern "\\s+", meaning "one or more whitespace characters", collapses the run and gives 2.
  • This is why real text-processing code tests words[i].isEmpty() before using a piece. Your instructor's word-scanning program does exactly that, and now you know what it is defending against.

The double backslash in "\\s" is not a typo either. \ starts an escape sequence inside a Java string literal, so to get a single backslash into the actual text you have to write two. The pattern that split finally receives is \s.

Example1.java

import java.util.Scanner;

public class Example1 {
    public static void main(String args[]) {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Enter some words: ");
        String input = scanner.nextLine();
        String[] words = input.split("\\s", -1);
        for (String s : words) {
            for (int i = s.length() - 1; i >= 0; i--) {
                System.out.print(s.charAt(i));
            }
            System.out.print(" ");
        }
        System.out.println();
        scanner.close();
    }
}

212 reversed is 212, which is a free correctness check while you are debugging.

There is one space too many: the program prints a space after every word, including the last, so the real output line ends with a trailing blank. It is invisible on screen and the rubric accepts it. If you wanted to avoid it, print the space before every word except the first.

Plan. Read a whole line, because the sentence has spaces in it. Walk it with the standard charAt loop. A character is upper case exactly when it lies between 'A' and 'Z' in the Unicode ordering — and since Lecture 1 you know a char is a number, so you can compare characters with >= and <= directly.

CountUppercase.java

import java.util.Scanner;

public class CountUppercase {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Enter a sentence: ");
        String sentence = scanner.nextLine();
        int count = 0;

        for (int i = 0; i < sentence.length(); i++) {
            char c = sentence.charAt(i);
            if (c >= 'A' && c <= 'Z') {
                count++;
            }
        }

        System.out.println("It has " + count + " upper-case characters.");
        scanner.close();
    }
}
Enter a sentence: Here Is A Long String.
It has 5 upper-case characters.

Things to notice. The five are H, I, A, L and S. The full stop and the spaces are not letters at all, and c >= 'A' && c <= 'Z' excludes them automatically because their code points are below 65.

Character.isUpperCase(c) does the same job in one call and handles accented letters correctly as well. Both answers are right; the range test is the one this question is steering you toward, since it says to use only length() and charAt.

Do not try c.equals('A') or c == "A". A char is a primitive, so it has no equals method, and comparing a char with a String will not compile. Single quotes for characters, double quotes for strings — the distinction from Quick Check 4.1 matters here.

Problem 6 — Remove repeated characters (from Exam 1 Practice Problems)

Write a private method called removeDuplicates that accepts a String parameter and returns a new String in which consecutive occurrences of a character are removed. Calling removeDuplicates("football") returns fotbal, after replacing the consecutive os by a single o and the consecutive ls by a single l. Similarly removeDuplicates("cookbook!!!") returns cokbok!.

Plan. "Consecutive" is the key word: you are comparing each character with the one immediately before it, not with every earlier character. So removeDuplicates("banana") is still banana — the as are not adjacent.

Walking from the end backwards lets you cut a character out without disturbing the positions you have not looked at yet. When str.charAt(i) equals str.charAt(i - 1), rebuild the string as everything before position i joined to everything after it. Remember that substring returns a new string, so the result has to be assigned back.

RemoveDup.java

public class RemoveDup {
    public static void main(String args[]) {
        System.out.println(removeDuplicates("football"));
        System.out.println(removeDuplicates("cookbook!!!"));
        System.out.println(removeDuplicates("Theee eeend."));
    }

    private static String removeDuplicates(String str) {
        if (str.length() <= 1) return str;
        for (int i = str.length() - 1; i > 0; i--) {
            if (str.charAt(i) == str.charAt(i - 1)) {
                str = str.substring(0, i) + str.substring(i + 1);
            }
        }
        return str;
    }
}
fotbal
cokbok!
The end.

Things to notice. str.substring(0, i) + str.substring(i + 1) is the general recipe for "the string with position i deleted", and the two calls fit together exactly because the first argument is inclusive and the second is exclusive: the first piece ends just before i, the second begins just after it.

The loop condition is i > 0, not i >= 0, because the body looks at i - 1 and position -1 does not exist. Getting that wrong gives you a StringIndexOutOfBoundsException on the very last iteration.

Reassigning the parameter str is safe and does not affect the caller's string — strings are immutable, so there is nothing to damage, and the caller's variable holds its own copy of the reference anyway.

A cleaner alternative builds the answer forward instead of cutting it down:

private static String removeDuplicates2(String str) {
    if (str.length() <= 1) return str;
    String answer = "" + str.charAt(0);
    for (int i = 1; i < str.length(); i++) {
        if (str.charAt(i) != str.charAt(i - 1)) {
            answer = answer + str.charAt(i);
        }
    }
    return answer;
}

Both produce the same three lines of output. The forward version reads more naturally and never modifies its input; the backward version is shorter. Either is a full-credit answer.

Problem 7 — Shorten every string in an array (from Exam 1 Practice Problems)

Write a function called shorten that is defined in the class Shorten and shortens each element of an array of strings. Every string with more than two characters is cut down to its first two characters.

Shorten.java

public class Shorten {
    public static void main(String args[]) {
        String x[] = {"CSCI", "1", "11", "Queens", "College", "CUNY"};
        shorten(x);
        for (int i = 0; i < 6; i++) System.out.print(x[i] + " ");
        // Output:   CS 1 11 Qu Co CU
        System.out.println();
    }
}

Plan. The method returns void and the caller sees the change, so shorten must modify the array itself. That is possible because arrays are mutable even though strings are not: you cannot shorten a String in place, but you can replace the reference stored in arr[i] with a reference to a shorter one.

Guard with length() > 2 so that "1" and "11" are left alone. "11".substring(0, 2) would be harmless, but "1".substring(0, 2) would throw.

Shorten.java

public class Shorten {
    public static void main(String args[]) {
        String x[] = {"CSCI", "1", "11", "Queens", "College", "CUNY"};
        shorten(x);
        for (int i = 0; i < 6; i++) System.out.print(x[i] + " ");
        System.out.println();
    }

    public static void shorten(String arr[]) {
        for (int i = 0; i < arr.length; i++) {
            if (arr[i].length() > 2) {
                arr[i] = arr[i].substring(0, 2);
            }
        }
    }
}
CS 1 11 Qu Co CU

Things to notice. arr[i] = arr[i].substring(0, 2); is the line the whole problem is about. The assignment is not optional and it is not cosmetic — without it, substring would build the shortened string and discard it, and the array would come out unchanged. This is Quick Check 4.6 again, wearing an array.

The method is void, yet the caller sees the result. That is because the array reference was passed in, and shorten reached through it to the caller's actual array. Contrast Problem 2, where reassigning a String parameter changed nothing outside the method: there the method moved its own copy of a tag; here it repacked a shared box.

Writing arr.length (no parentheses) for the array and arr[i].length() (with parentheses) for the string on adjacent lines is not a trick question — it is just Java's inconsistency, and you will get used to it.

Problem 8 — What is the output? (added for these notes)

This one puts immutability and the string pool in the same program.

Mystery.java

public class Mystery {
    public static void main(String args[]) {
        String s = "csci";

        shout(s);
        System.out.println(s);                     // line (a)
        s = shoutBack(s);
        System.out.println(s);                     // line (b)

        String t = "csci";
        System.out.println(s == t);                // line (c)
        System.out.println(s.equalsIgnoreCase(t)); // line (d)
        System.out.println(t.equals(s.toLowerCase()));  // line (e)
        System.out.println(t.substring(1) + t.length()); // line (f)
    }

    static void shout(String x) {
        x = x.toUpperCase();
    }

    static String shoutBack(String x) {
        return x.toUpperCase();
    }
}

(a) What is printed at line (a)?

csci. shout reassigns its own parameter x, which is a copy of the reference. The caller's variable s never moves. Even if the method had somehow "changed" the string it could not have, because strings are immutable.

(b) What is printed at line (b)?

CSCI. shoutBack returns the new string, and main catches it with s = .... This is the only way to get a value back out of a method here: return it and assign it.

(c) What is printed at line (c)?

false. s is now CSCI, t is csci. Different characters and different objects, so the answer would be false however you asked.

(d) What is printed at line (d)?

true. CSCI and csci are the same once case is ignored.

(e) What is printed at line (e)?

true. s.toLowerCase() builds a new string csci, and equals compares its characters with t's. It does not matter in the slightest that this is a third object; equals never asks.

(f) What is printed at line (f)?

sci4. t.substring(1) is sci, and t.length() is 4. The left operand of + is already a String, so the 4 is concatenated rather than added.

Things to notice across all six parts. Lines (a) and (b) are the same method body called two ways, and they are the difference between a method that appears to work and one that does. If a method's job is to produce a new string, it must return it — a void method that reassigns a String parameter can never accomplish anything.

Compare that with Problem 7, where a void method did change what the caller saw. The difference is that Problem 7 modified an array element through a shared reference; here there is no shared mutable object at all, because strings are immutable. Both facts come from the same rule: Java copies the reference, and whether the caller notices depends entirely on whether the object it points at can be changed.

Lecture Summary
  • String is a class, not a primitive. A String variable holds a reference to an object, not the text itself.
  • Two ways to create one. A literal "abc" goes into the string pool and is shared by every other identical literal; new String("abc") always builds a separate object outside the pool.
  • == compares references; .equals compares contents. Two literals with the same text are ==; a literal and a new String with the same text are not. Use .equals — or .equalsIgnoreCase — whenever you mean "do these say the same thing?"
  • compareTo returns an int: negative if the receiver comes first, zero if equal, positive if it comes last. Capitals sort before lowercase.
  • Strings are immutable. trim, toUpperCase, replace, substring, concat and + all return a new string and leave the original alone. If you do not assign the result, nothing happens.
  • Positions run from 0 to length() - 1. length(), charAt(i) and isEmpty() let you walk a string one character at a time, and that loop solves most string exercises.
  • substring(begin) runs to the end; substring(begin, end) excludes end, so the result is end - begin characters long.
  • indexOf and lastIndexOf return a position or -1 when there is no match; contains asks the same question and answers with a boolean.
  • split cuts a string into an array of pieces, removing only the separator. Consecutive separators leave empty pieces behind.
