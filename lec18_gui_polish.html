1.Where we are, and what is left

Three lectures ago a window was an empty rectangle. Since then you have learned everything you need to build a real interface. Lecture 15 gave you the window itself — a class that extends JFrame, sized in its constructor, shown with setVisible(true), closed properly with setDefaultCloseOperation — and the event model: a source fires an event, a listener you wrote handles it. Lecture 16 gave you the layout managers that decide where components go, and the JButton that made the event model worth having. Lecture 17 gave you the components people actually type into and choose from: JTextField, JTextArea, JLabel, and menus.

What is left is small, and that is the point of today. Nothing in this lecture changes how a program works. Everything in it changes how a program looks — with one exception, the scroll pane, which changes what a program can hold.

Key Idea— three tools, one afternoon

Borders draw a line, a groove or a title around a component, and are the cheapest way to show a user that four controls belong together. Icons put a picture on a label or a button. A scroll pane wraps one component so that a small area on screen can show a large amount of content.

Each of the three is one extra line of code applied to a component you already know how to make. There is no new mechanism here — only new methods.

Because there is room, the last section of this lecture does something the previous three could not: it builds a complete small application that uses all of it at once. That combination — a frame holding nested panels laid out by layout managers, with buttons at the bottom, a text area in a scroll pane in the middle, and borders holding the groups apart — is exactly the shape of the GUI questions on your exams.

2.Borders and the BorderFactory class

Definition— border

A border is an object that draws a decoration around the edge of a component. Borders add visual distinction, helping to separate and organize the interface.

Four facts about them are worth memorizing, because they answer most of the questions students ask:

  • A border can be applied to any JComponent — a panel, a label, a button, a text field, a scroll pane.
  • Borders do not affect where a component is placed. The layout manager decides that. A border only changes appearance, and how much room is left inside.
  • Borders can be combined and nested.
  • They exist to create visual hierarchy: a titled box around three buttons says "these three go together" without a word of explanation.

You almost never call a border constructor directly. Instead you ask a factory class for one.

Definition— BorderFactory

BorderFactory, in javax.swing, is a class of static methods that each return a ready made Border object. You never write new BorderFactory() — there is nothing to construct. You call the methods on the class itself, exactly the way you call Math.sqrt.

The Border interface itself, and the individual border classes, live in a different package: javax.swing.border. So a program that declares a variable of type Border needs both imports.

import javax.swing.BorderFactory;
import javax.swing.border.Border;

These are the six kinds you need, with the factory call that makes each one:

TypeWhat it looks likeHow you make one
LineBorderA simple solid line around the component.BorderFactory.createLineBorder(Color.RED, 3)
TitledBorderA thin line with a caption written into the top edge.BorderFactory.createTitledBorder("Panel Title")
EtchedBorderA two-tone groove, as if carved into the surface.BorderFactory.createEtchedBorder()
BevelBorderA shaded edge that makes the component look raised or sunken.BorderFactory.createRaisedBevelBorder()
BorderFactory.createLoweredBevelBorder()
EmptyBorderNothing at all — invisible space. Used as padding.BorderFactory.createEmptyBorder(10, 10, 10, 10)
CompoundBorderTwo borders at once, one inside the other.BorderFactory.createCompoundBorder(outer, inner)

Applying one is a single method call on the component:

JPanel panel = new JPanel();
panel.setBorder(BorderFactory.createLineBorder(Color.RED, 3));
Quick Check 18.1

Which of these lines compile? For any that do not, say why.

(a) myButton.setBorder(BorderFactory.createEtchedBorder());

Compiles. JButton is a JComponent, and setBorder is declared in JComponent, so every Swing component inherits it. Whether the button's look-and-feel then draws your border instead of its own is a separate question — but the line is legal.

(b) getContentPane().setBorder(BorderFactory.createEtchedBorder());

Does not compile. getContentPane() is declared to return a java.awt.Container, and Container is an AWT class that predates Swing by years. It has no setBorder method — that method belongs to JComponent.

This is important enough that §3 gives it its own warning box, together with the two ways round it.

(c) panel.setBorder(new BorderFactory().createLineBorder(Color.RED, 2));

Does not compile, and it also misunderstands what a factory class is. Every method in BorderFactory is static, so you call it on the class: BorderFactory.createLineBorder(...). There is no public constructor to call.

(d) panel.setBorder(new EtchedBorder(Color.GREEN, Color.BLUE));

Compiles, given import javax.swing.border.EtchedBorder;. The factory is a convenience, not a rule: every border class has ordinary public constructors, and this one takes the highlight color and the shadow color of the groove. Your instructor's NameTester example below uses exactly this form.

Things to notice across all four parts. Two separate packages are in play and they are easy to mix up. BorderFactory is in javax.swing; the Border interface and all the border classes are in javax.swing.border. If your import list says import javax.swing.*; you have the factory but not the classes, which is why code that declares a Border variable so often needs a second import line.

Worked Example— all six borders in one window

This is your instructor's BorderDemo. Six panels in a three-by-two grid, each with one kind of border and a label naming it. Read it and predict two things before you reveal: how the six panels are arranged, and what the sixth one looks like compared with the first.

Worked Example— a border on a text field

NameTester divides the window into two equal rows with a GridLayout(2, 1). The top row is a panel holding a prompt and a text field; the bottom row holds two buttons. The only new line is the one that borders the text field.

NameTester.java

import java.awt.Color;
import java.awt.Container;
import java.awt.FlowLayout;
import java.awt.GridLayout;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;

import javax.swing.JButton;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.JTextField;
import javax.swing.border.EtchedBorder;

public class NameTester extends JFrame implements ActionListener {
   public static final int WIDTH = 400;
   public static final int HEIGHT = 300;

   private Container content;
   private JTextField name;

   public NameTester() {
      super();
      setSize(WIDTH, HEIGHT);
      setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
      setTitle("Name Tester with borders");
      content = getContentPane();
      content.setLayout(new GridLayout(2, 1));

      JPanel namePanel = new JPanel();
      namePanel.setLayout(new BorderLayout());
      namePanel.setBackground(Color.WHITE);
      content.add(namePanel);

      name = new JTextField(20);
      name.setBorder(new EtchedBorder(Color.GREEN, Color.BLUE));
      namePanel.add(name, BorderLayout.SOUTH);
      JLabel nameLabel = new JLabel("Enter your name here: ");
      namePanel.add(nameLabel, BorderLayout.CENTER);

      buttonPanel.setLayout(new FlowLayout());

      b.addActionListener(this);

      b.addActionListener(this);
      buttonPanel.add(b);

      if (e.getActionCommand().equals("Clear")) name.setText("");

The window is 400 by 300 and split into two equal halves. The top half is white, with the words Enter your name here: at the left of the middle and a text field pinned across the bottom of that half — because BorderLayout.SOUTH stretches a component across the full width of its container. 3.What a border costs: insets, padding and compound borders

A border is drawn inside the component's rectangle, not outside it. So every border takes space away from the interior, and the amount it takes has a name.

Definition— insets

The insets of a border are the four distances — top, left, bottom, right — by which it shrinks the usable interior of the component. A java.awt.Insets object is just those four int values with those four names.

You will rarely ask for them in real code. Knowing them matters because they explain why a component with a border has less room in it than you expected, and because a compound border's insets are the arithmetic sum of its two parts.

Unlike the window itself, insets are something we can measure without a screen. The following program builds each border, asks it for its insets, and prints them.

Worked Example— measuring six borders

Predict four numbers before you reveal. How thick is a 3-pixel line border? An etched border? An EmptyBorder(10, 10, 10, 10)? And what does a compound border made from a 2-pixel line outside and that same empty border inside come to?

Key Idea— the EmptyBorder trick

BorderFactory.createEmptyBorder(top, left, bottom, right) draws nothing at all. Applied to a panel, it is the standard way to put a margin around a group of components — and it is the single most useful thing in this lecture, because every layout manager in Lecture 16 pushes components right up against the edge of their container.

JPanel main = new JPanel();
main.setLayout(new BorderLayout());
main.setBorder(BorderFactory.createEmptyBorder(10, 10, 10, 10));  // a 10px margin

In Lecture 15 we padded a label by writing two spaces into its text: new JLabel(" Hello"). That is a hack, and this is the fix.

Definition— CompoundBorder

BorderFactory.createCompoundBorder(outer, inner) makes one border out of two. The first argument is drawn on the outside, the second inside it, and the insets add up.

The overwhelmingly common use is "a visible border, plus breathing room inside it":

Border outer = BorderFactory.createTitledBorder("Options");
Border inner = BorderFactory.createEmptyBorder(8, 8, 8, 8);
panel.setBorder(BorderFactory.createCompoundBorder(outer, inner));

Nesting is not limited to two. A compound border is itself a Border, so it can be the outer or the inner argument of another compound border.

Common Mistake— setBorder on the content pane

This is the first thing everybody tries, and it does not compile:

Container contentPane = getContentPane();
contentPane.setBorder(BorderFactory.createEtchedBorder());

      contentPane.setBorder(BorderFactory.createEtchedBorder());
                 ^
  symbol:   method setBorder(Border)

Read the last line of the message: location: variable contentPane of type Container. getContentPane() is declared to return java.awt.Container, an AWT class from 1995, and setBorder was introduced later, in Swing's JComponent. The method genuinely is not there.

The fix that always works is to put your own JPanel inside the content pane and border that. It is one extra object and it gives you somewhere to hang the margin for the whole window:

PaneBorder2.java

import javax.swing.BorderFactory;
import javax.swing.JFrame;
import javax.swing.JPanel;

public class PaneBorder2 extends JFrame {
   public PaneBorder2() {
      super("Pane Border");
      setSize(300, 200);
      JPanel main = new JPanel();
      main.setBorder(BorderFactory.createEmptyBorder(10, 10, 10, 10));
      getContentPane().add(main);
   }

   public static void main(String args[]) {
      PaneBorder2 gui = new PaneBorder2();
      gui.setVisible(true);
   }
}

There is a second fix — casting, because a JFrame's content pane really is a JPanel underneath — and it is worth knowing it exists:

((JPanel) getContentPane()).setBorder(BorderFactory.createEmptyBorder(10, 10, 10, 10));

It compiles and it works, but it depends on a fact the return type does not promise you. Use the extra panel.

Write a complete class Framed that extends JFrame and shows a 300 by 200 window titled Framed. import java.awt.BorderLayout;
import java.awt.Color;

import javax.swing.BorderFactory;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.border.Border;

public class Framed extends JFrame {
   public static final int WIDTH = 300;
   public static final int HEIGHT = 200;

      setSize(WIDTH, HEIGHT);
      setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

      JPanel panel = new JPanel();
      Border line = BorderFactory.createLineBorder(Color.RED, 5);
      Border pad  = BorderFactory.createEmptyBorder(20, 20, 20, 20);
      panel.setBorder(BorderFactory.createCompoundBorder(line, pad));

   }

      Framed gui = new Framed();

   }

javac Framed.java succeeds. The window shows a panel filling the whole content pane, outlined in a thick red rectangle, with the word Bordered centered near the top of the panel — not vertically centered, because the panel's own default FlowLayout puts its contents in a row at the top.

Things to notice. The panel fills the entire window because a lone component added to a BorderLayout content pane goes in the center and is stretched, exactly as in Lecture 15. So the red rectangle traces the inside edge of the window.

Order matters in createCompoundBorder(line, pad). Swap the arguments and you get 20 pixels of invisible space and then the red line, so the rectangle shrinks inward and hugs the label instead of the window. Both compile; only one is what the question asked for.

The total insets are 25 on every side — 5 from the line, 20 from the padding — which is what the BorderProbe output above would show if you added this border to it.

Quick Check 18.4

A panel is 200 pixels wide and 100 tall. You give it createCompoundBorder(createLineBorder(Color.BLACK, 4), createEmptyBorder(6, 6, 6, 6)).

(a) What are the insets of that border?

10 on every side: 4 from the line plus 6 from the empty border. CompoundBorder adds the two sets of insets edge by edge.

(b) How much room is left inside the panel for its contents?

180 by 80. The border eats 10 pixels from the left and 10 from the right, so 200 − 20 = 180; likewise 100 − 20 = 80.

This is why a text field inside a heavily bordered panel can end up too narrow to show the text you put in it, when the same field looked fine before you added the border.

(c) Does the panel move on the screen when you add the border?

No. Its position and size are decided by its container's layout manager, and a border does not participate in that decision. What changes is only how much of the panel's own rectangle is available to whatever the panel contains.

Things to notice across all three parts. A border shrinks the inside, never the outside. When something you added to a panel disappears after you border the panel, the border did not push it out of the window — it left too little interior for the layout manager to place it in.

4.Icons on labels and buttons

Definition— Icon and ImageIcon

An icon is a small fixed-size picture that a Swing component can draw. In Java, icons are described by the interface Icon in javax.swing, which has three methods: paint yourself, say how wide you are, say how tall you are.

ImageIcon is the class almost everybody uses. It implements Icon by loading a picture from a file, a URL or a resource inside a jar. The constructor you need takes a file name:

ImageIcon dukeWavingIcon = new ImageIcon("duke_waving.gif");

Icons are used to add visual elements to buttons, labels and menu items. Every component that shows text can show an icon as well — JLabel, JButton, JMenuItem and several others all have a setIcon method.

5.When the image file is not there

Icons are the one part of this lecture with a dependency outside your source code, and that dependency is where the trouble is. It is worth being blunt about the situation in these notes: the image files your instructor's IconDemo loads — duke_waving.gif and duke_standing.gif — are not part of the code you have. They sat in her project folder alongside the .java files. So the program compiles here and everywhere, and it runs, but it cannot show you those two pictures unless you supply your own.

Warning— where the file has to be

new ImageIcon("duke_waving.gif") is a relative file name, and Java resolves it against the current working directory of the running program — which, when you type java IconDemo in a terminal, is the directory you are standing in. In practice that means the image must sit next to the .class file you are running.

Two consequences that catch people out:

  • Running the same program from a different directory breaks the icon, without changing a line of code.
  • An absolute path such as "/Users/name/Desktop/CSCI 212/src/Lecture_17/duke_waving.gif" works on exactly one computer. If you submit code with a path like that in it, nobody else can run it. Use a plain file name and hand in the image with the source.

So what actually happens when the file is missing? This is worth knowing precisely, because the behavior is not what most students guess.

Worked Example— a missing image, measured

An ImageIcon is an ordinary object, and asking it how big it is needs no window — so unlike the rest of this lecture, this one we can genuinely run. There is no duke_waving.gif in this directory. Before you reveal, predict: does the constructor throw an exception? Does the program crash? What comes back from getIconWidth()?

No exception. No error message. No crash. The constructor succeeds, you get a perfectly valid ImageIcon object, and the only evidence that anything went wrong is that the icon reports a width and a height of −1 and a load status of 4, which is MediaTracker.ERRORED.

That is why a missing image is such a confusing bug. Put this icon on a button and the button appears exactly where you expect, with its text, and simply no picture — there is nothing for it to draw. ImageIcon icon = new ImageIcon("save.png");
if (icon.getIconWidth() < 0)
   System.out.println("WARNING: save.png could not be loaded");

A width of −1 is the sign of a failed load, because a real image always has a positive width. Testing getImageLoadStatus() == MediaTracker.COMPLETE is the more explicit version of the same check.

6.JScrollPane: a small window onto a large component

Everything so far has been decoration. The scroll pane is not: it is the component that lets a 300-pixel window display a thousand lines of text.

Definition— JScrollPane

A JScrollPane is a container that adds scrolling capability to one other component. Scroll bars in Swing are almost never created directly; they are added by putting the component in a scroll pane.

  • It automatically adds a horizontal or vertical scroll bar when the content is bigger than the visible area.
  • It works with many components: JTextArea, JList, JTable, JTree, and custom components.
  • It supports smooth scrolling and keyboard navigation with no work from you.
  • Its visibility rules can be customized — that is §7.

You build one by handing the component to the constructor:

JTextArea textArea = new JTextArea(5, 20);
JScrollPane scrollPane = new JScrollPane(textArea);
Key Idea— add the wrapper, not the thing inside it

Once a component is inside a scroll pane, the scroll pane is the thing you add to the window. The component is no longer added anywhere — the scroll pane holds it.

contentPane.add(scrollPane, BorderLayout.CENTER);   // right
contentPane.add(textArea,   BorderLayout.CENTER);   // wrong, and it compiles

Both lines compile. Only one of them scrolls.

That second line is the single most common mistake in this whole lecture, and it deserves an explanation of exactly why it fails, because the failure is worse than it looks.

Common Mistake— adding the component instead of the scroll pane

A component in Java has at most one parent. Adding it somewhere else does not copy it — it moves it. So writing contentPane.add(textArea) after you have already wrapped textArea in a scroll pane quietly rips the text area out of the scroll pane's viewport, and you are left with two broken things: a text area that does not scroll, and an empty scroll pane that is not in the window at all.

This one we can demonstrate for real, because none of it needs a screen. A JPanel stands in for the content pane.

ScrollProbe.java

import javax.swing.JPanel;
import javax.swing.JScrollPane;
import javax.swing.JTextArea;

   public static void show(String label, JTextArea area, JScrollPane scroll) {
      System.out.println(label);
      System.out.println("   the text area's parent is  " + name(area.getParent()));
      System.out.println("   the viewport now holds     " + name(scroll.getViewport().getView()));
   }

   private static String name(Object o) {
      if (o == null) return "null";
      return o.getClass().getName();
   }

   public static void main(String args[]) {
      JTextArea area = new JTextArea(5, 20);
      JScrollPane scroll = new JScrollPane(area);
      JPanel contentPane = new JPanel();          // stands in for getContentPane()

      show("After new JScrollPane(area):", area, scroll);

      contentPane.add(area);                      // THE MISTAKE

      contentPane.add(scroll);                    // the correct line
      System.out.println("After contentPane.add(scroll):");
      System.out.println("   the scroll pane's parent is " + name(scroll.getParent()));
   }
}

7.The three scroll bar policies

By default a scroll bar appears when it is needed and vanishes when it is not. Sometimes you want something steadier — a bar that is always there, so the layout never jumps — or none at all.

Definition— scroll bar policies

A scroll pane has two independent policies, one per bar, each set by a method that takes an int constant:

MethodConstantMeaning
setVerticalScrollBarPolicy(int)JScrollPane.VERTICAL_SCROLLBAR_AS_NEEDEDShow the bar only when the content is too tall. The default.
JScrollPane.VERTICAL_SCROLLBAR_ALWAYSAlways show it, even when everything fits.
JScrollPane.VERTICAL_SCROLLBAR_NEVERNever show it. The content can still be scrolled by keyboard or wheel.
setHorizontalScrollBarPolicy(int)JScrollPane.HORIZONTAL_SCROLLBAR_AS_NEEDEDSame three rules, for the bar along the bottom. The default.
JScrollPane.HORIZONTAL_SCROLLBAR_ALWAYS
JScrollPane.HORIZONTAL_SCROLLBAR_NEVER

The constants are ordinary int values, and you can see them:

VERTICAL_SCROLLBAR_AS_NEEDED   = 20
VERTICAL_SCROLLBAR_NEVER       = 21
VERTICAL_SCROLLBAR_ALWAYS      = 22
HORIZONTAL_SCROLLBAR_AS_NEEDED = 30
HORIZONTAL_SCROLLBAR_NEVER     = 31
HORIZONTAL_SCROLLBAR_ALWAYS    = 32
default vertical policy        = 20
default horizontal policy      = 30

Never write the numbers. They are shown here only so that the two families are obviously separate: passing a vertical constant to setHorizontalScrollBarPolicy compiles perfectly — they are all just int — and then throws an IllegalArgumentException when the line runs.

ScrollBarDemo.java

import java.awt.BorderLayout;
import java.awt.Container;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;

import javax.swing.BorderFactory;
import javax.swing.JButton;
import javax.swing.JFrame;
import javax.swing.JPanel;
import javax.swing.JScrollPane;
import javax.swing.JTextArea;

public class ScrollBarDemo extends JFrame implements ActionListener {
   public static final int WIDTH = 500;
   public static final int HEIGHT = 300;

   private JTextArea textArea;
   private JScrollPane scrollPane;

   public ScrollBarDemo() {
      super("ScrollBar Demonstration");
      setSize(WIDTH, HEIGHT);
      setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

      Container contentPane = getContentPane();
      contentPane.setLayout(new BorderLayout());

      // A text area with far more content than fits.
      textArea = new JTextArea(5, 20);
      StringBuilder text = new StringBuilder();
      for (int i = 1; i <= 100; i++) {
         text.append("Line ").append(i).append(" of sample text.\n");
      }
      textArea.setText(text.toString());

      // Wrap it. The scroll pane is what goes in the frame.
      scrollPane = new JScrollPane(textArea);
      scrollPane.setBorder(BorderFactory.createTitledBorder("Text with ScrollBars"));
      scrollPane.setVerticalScrollBarPolicy(JScrollPane.VERTICAL_SCROLLBAR_ALWAYS);
      scrollPane.setHorizontalScrollBarPolicy(JScrollPane.HORIZONTAL_SCROLLBAR_AS_NEEDED);
      contentPane.add(scrollPane, BorderLayout.CENTER);

      JPanel controlPanel = new JPanel();
      controlPanel.setBorder(BorderFactory.createTitledBorder("ScrollBar Policies"));

      JButton verticalAlways = new JButton("Vertical Always");
      verticalAlways.addActionListener(this);

      JButton verticalNever = new JButton("Vertical Never");
      verticalNever.addActionListener(this);

      JButton verticalNeeded = new JButton("Vertical As Needed");
      verticalNeeded.addActionListener(this);

      controlPanel.add(verticalAlways);
      controlPanel.add(verticalNever);
      controlPanel.add(verticalNeeded);

      contentPane.add(controlPanel, BorderLayout.SOUTH);
   }

   public void actionPerformed(ActionEvent e) {
      String command = e.getActionCommand();

      if (command.equals("Vertical Always")) {
         scrollPane.setVerticalScrollBarPolicy(JScrollPane.VERTICAL_SCROLLBAR_ALWAYS);
      } else if (command.equals("Vertical Never")) {
         scrollPane.setVerticalScrollBarPolicy(JScrollPane.VERTICAL_SCROLLBAR_NEVER);
      } else if (command.equals("Vertical As Needed")) {
         scrollPane.setVerticalScrollBarPolicy(JScrollPane.VERTICAL_SCROLLBAR_AS_NEEDED);
      }
   }

   public static void main(String[] args) {
      ScrollBarDemo demo = new ScrollBarDemo();
      demo.setVisible(true);
   }
}

8.Putting it all together

Four lectures of GUI material now fit into one program. This section builds a small but complete application — a memo pad with two save slots — using nothing you have not met:

  • a class that extends JFrame implements ActionListener, from Lecture 15;
  • nested JPanels with BorderLayout and GridLayout, from Lecture 16;
  • JButtons sharing one actionPerformed, told apart by getActionCommand(), from Lecture 16;
  • a JTextArea and a JLabel used for status, from Lecture 17;
  • and from today: a scroll pane around the text area, and four borders holding the layout apart.

It is deliberately built the way an exam answer should be built, and there is one design idea in it that is not about Swing at all.

Procedure— how to write a GUI class, every time
  1. The header. public class Name extends JFrame implements ActionListener. If nothing is clicked, drop the implements.
  2. The fields. Every component a listener has to reach, plus the size constants. Everything else can be a local variable in the constructor.
  3. The frame itself. super("Title"), setSize, setDefaultCloseOperation.
  4. One main panel inside the content pane, with an EmptyBorder — that is the whole window's margin, and it is the reason the result does not look cramped.
  5. The regions. Give the main panel a BorderLayout and fill NORTH, CENTER and SOUTH with panels of their own. Anything scrollable goes in a JScrollPane, and it is the scroll pane you add.
  6. The borders. A titled border on any group that needs a name; a bevel on a status line; padding wherever two things touch.
  7. The listener. One actionPerformed, one if/else if chain on getActionCommand(), and a addActionListener(this) on every button.
  8. main. Two lines: build it, show it.

First, the piece that is not Swing. The memo pad has to remember two strings; that is not a user interface problem, so it does not belong in the frame.

Worked Example— the model, and why it is separate

MemoStore knows nothing about windows. It is an ordinary class of the kind you have been writing since Lecture 7, and because it has no Swing in it, it can be tested by an ordinary main that prints things.

Worked Example— MemoPad: the whole application

MemoPad.java

import java.awt.BorderLayout;
import java.awt.Container;
import java.awt.GridLayout;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;

import javax.swing.BorderFactory;
import javax.swing.JButton;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.JScrollPane;
import javax.swing.JTextArea;
import javax.swing.border.Border;

public class MemoPad extends JFrame implements ActionListener {
   public static final int WIDTH = 520;
   public static final int HEIGHT = 380;

   private JTextArea theText;      // where the user types
   private JLabel status;          // one line of feedback at the top
   private MemoStore store;        // the model: two saved strings

   public MemoPad() {
      super("Memo Pad");
      setSize(WIDTH, HEIGHT);
      setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

      store = new MemoStore();

      // ---- one main panel, so the whole window gets a margin -------------
      JPanel main = new JPanel();
      main.setLayout(new BorderLayout(8, 8));
      main.setBorder(BorderFactory.createEmptyBorder(10, 10, 10, 10));
      Container contentPane = getContentPane();
      contentPane.add(main);

      // ---- NORTH: a status line in a lowered bevel ------------------------
      status = new JLabel(" Type a memo, then save it in slot 1 or slot 2.");
      status.setBorder(BorderFactory.createLoweredBevelBorder());
      main.add(status, BorderLayout.NORTH);

      // ---- CENTER: the text area, wrapped in a scroll pane ----------------
      theText = new JTextArea(10, 40);
      theText.setLineWrap(true);
      theText.setWrapStyleWord(true);
      JScrollPane scroll = new JScrollPane(theText);
      scroll.setVerticalScrollBarPolicy(JScrollPane.VERTICAL_SCROLLBAR_ALWAYS);
      scroll.setHorizontalScrollBarPolicy(JScrollPane.HORIZONTAL_SCROLLBAR_NEVER);
      scroll.setBorder(BorderFactory.createTitledBorder("Memo text"));
      main.add(scroll, BorderLayout.CENTER);      // the SCROLL PANE, not theText

      // ---- SOUTH: five buttons in a row -----------------------------------
      JPanel buttonPanel = new JPanel();
      buttonPanel.setLayout(new GridLayout(1, 5, 6, 6));
      Border padding = BorderFactory.createEmptyBorder(6, 0, 0, 0);
      buttonPanel.setBorder(BorderFactory.createCompoundBorder(
                               BorderFactory.createTitledBorder("Actions"), padding));
      makeButton(buttonPanel, "Save 1");
      makeButton(buttonPanel, "Save 2");
      makeButton(buttonPanel, "Get 1");
      makeButton(buttonPanel, "Get 2");
      makeButton(buttonPanel, "Clear");
      main.add(buttonPanel, BorderLayout.SOUTH);
   }

   private void makeButton(JPanel panel, String buttonName) {
      JButton b = new JButton(buttonName);
      panel.add(b);
      b.addActionListener(this);
   }

   public void actionPerformed(ActionEvent e) {
      String command = e.getActionCommand();

      if (command.equals("Save 1")) {
         store.save(1, theText.getText());
         status.setText(" Saved to slot 1.");
      } else if (command.equals("Save 2")) {
         store.save(2, theText.getText());
         status.setText(" Saved to slot 2.");
      } else if (command.equals("Get 1")) {
         theText.setText(store.get(1));
         status.setText(" Loaded slot 1.");
      } else if (command.equals("Get 2")) {
         theText.setText(store.get(2));
         status.setText(" Loaded slot 2.");
      } else if (command.equals("Clear")) {
         theText.setText("");
         status.setText(" Cleared. Nothing was saved.");
      }
   }

   public static void main(String args[]) {
      MemoPad gui = new MemoPad();
      gui.setVisible(true);
   }
}

Common Mistake— a scroll pane that will not grow

A version of this program that puts the scroll pane inside an extra plain panel:

JPanel textPanel = new JPanel();          // default FlowLayout
textPanel.add(scroll);
main.add(textPanel, BorderLayout.CENTER);

compiles and looks nearly right — until you resize the window. A JPanel uses FlowLayout by default, and FlowLayout gives every component exactly its preferred size and never stretches it. So the text area stays frozen at ten rows by forty columns in the middle of an expanding grey area.

Add the scroll pane directly to the BorderLayout region, as MemoPad does, and BorderLayout stretches it to fill the space. If you do need a panel in between, give that panel a BorderLayout too.

Quick Check 18.11

In MemoPad, theText and status are private fields while scroll and buttonPanel are local variables in the constructor. Explain the rule that decides which is which, and say what would break if theText were made a local variable instead.

Plan. Ask, for each component, "does any code outside the constructor need to reach this object?" A constructor's local variables cease to exist the moment it returns. A field lives as long as the window does.

The rule: a component must be a field if and only if a method other than the constructor uses it. In MemoPad that means theText (read by Save, written by Get and Clear), status (written by all five buttons), and store (used by four of them). Nothing ever refers to scroll, main, buttonPanel or any individual JButton again after the window is built, so they stay local — and keeping them local is a positive good, because a field is a promise that something will use it later.

If theText were local, the class would fail to compile: actionPerformed would contain theText.getText() with no such name in scope, and javac would report cannot find symbol ... variable theText. Nothing subtle happens — you simply cannot write the listener.

Things to notice. This is the same question as "which variables does my listener close over", and it is why so many GUI classes have a block of private fields at the top followed by a long constructor. When an exam question hands you a class skeleton with JPanel center; or JTextField input, output; already declared, it is telling you which components the listener is expected to touch. Read that line as a hint about the answer.

Quick Check 18.12

Three quick decisions about the same program.

(a) You want the memo pad's five buttons to be their natural widths and centered, rather than five equal-width buttons filling the row. What one line changes?

Delete buttonPanel.setLayout(new GridLayout(1, 5, 6, 6));, or replace it with buttonPanel.setLayout(new FlowLayout());. FlowLayout is a JPanel's default and gives every component its preferred size, centered in a row. GridLayout forces them all to the same size. Neither is more correct; they are two looks.

(b) You want a small picture on the Clear button as well as the word. Which line changes, and what has to be true for it to work?

Inside makeButton, or on that one button: b.setIcon(new ImageIcon("clear.png"));. For anything to appear, clear.png must be in the directory the program is run from — and if it is not, you get a button with the word Clear, no picture, and no error message at all, as §5 showed.

(c) Somebody suggests deleting MemoStore and keeping the two strings as fields of MemoPad. Would the program still work? Is it a good idea?

It would work perfectly. Two private String fields and the same if chain, and nothing on the screen changes.

What you lose is the MemoStoreDemo output — the ability to check the rules of the program by running something. With the strings inside the frame, testing them means opening a window and clicking, which is slow, manual, and impossible on a machine with no display. For a two-string memo pad that hardly matters. For anything with real rules in it, keeping the logic out of the window is the difference between a program you can test and one you can only try.

Problem 3 — Short answer (added for these notes)

Six one-or-two-sentence questions of the kind that open a GUI exam problem.

(a) Name the six border types produced by BorderFactory and say in one phrase what each looks like.

LineBorder — a plain line. TitledBorder — a line with a caption in its top edge. EtchedBorder — a two-tone groove. BevelBorder — a shaded edge making the component look raised or lowered. EmptyBorder — invisible space, used as padding. CompoundBorder — two borders, one inside the other.

(b) Why does getContentPane().setBorder(...) not compile, and what do you write instead?

getContentPane() is declared to return java.awt.Container, and setBorder is declared in javax.swing.JComponent, which Container knows nothing about. Add a JPanel to the content pane and set the border on that panel.

(c) A panel has createCompoundBorder(createLineBorder(Color.BLACK, 3), createEmptyBorder(5, 5, 5, 5)). What are its insets?

8 on all four sides. A compound border's insets are the sum of the outer and inner insets.

(d) Where must an image file be for new ImageIcon("logo.png") to find it, and what happens if it is not there?

The name is relative to the directory the program is run from, so in practice the file must sit beside the .class file you are running. If it is missing, no exception is thrown: you get a valid ImageIcon whose getIconWidth() is −1 and whose load status is MediaTracker.ERRORED, and the component draws its text and no picture.

(e) Give the two lines that make a JTextArea called notes scrollable inside a BorderLayout content pane.

JScrollPane scroll = new JScrollPane(notes);
contentPane.add(scroll, BorderLayout.CENTER);

The second line is the one that matters. Adding notes there instead compiles and produces a text area with no scroll bars.

(f) What is the default vertical scroll bar policy, and when would you change it to ALWAYS?

The default is VERTICAL_SCROLLBAR_AS_NEEDED: the bar appears only when the content is too tall. You choose ALWAYS when you do not want the layout to shift the moment the content grows past the bottom edge — the bar's width is reserved from the start.

Things to notice across all six parts. Four of the six are one-line facts and two are about what happens when something is missing. That ratio is not an accident: the borders and icons themselves are easy, and everything that is hard about them is a failure that produces no error message.

Problem 5 — Write a complete application (added for these notes)

Write a complete class ReadingList that extends JFrame implements ActionListener and produces a window 480 by 360 titled Reading List, laid out like this:

  • A margin of 10 pixels around the whole interior.
  • Across the top, inside a titled border reading Add a book: the label Title:, a text field 20 columns wide, and an Add button.
  • Filling the middle: a non-editable JTextArea of 10 rows by 30 columns, scrollable, inside a titled border reading My list.
  • At the bottom: a Clear button.

Clicking Add appends the text field's contents to the text area as a new line and empties the field. Clicking Clear empties the text area. Clicking the close box ends the program.

Plan. Follow the eight-step procedure from §8 without deviating.

  • Header: extends JFrame implements ActionListener, because there are buttons.
  • Fields: title and list, because actionPerformed touches both. Nothing else.
  • A main panel with BorderLayout(8, 8) and a 10-pixel EmptyBorder.
  • NORTH is a panel with its default FlowLayout — a label, a field and a button in a row is exactly what FlowLayout is for — wearing the titled border.
  • CENTER is the scroll pane, not the text area, wearing the other titled border.
  • SOUTH is a panel holding one button.
  • Both buttons get addActionListener(this).

list.setEditable(false) because the list is built by the Add button, not typed into. Appending with append(text + "\n") rather than setText is what keeps the earlier entries.

ReadingList.java

import java.awt.BorderLayout;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;

import javax.swing.BorderFactory;
import javax.swing.JButton;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.JScrollPane;
import javax.swing.JTextArea;
import javax.swing.JTextField;

public class ReadingList extends JFrame implements ActionListener {
   public static final int WIDTH = 480;
   public static final int HEIGHT = 360;

   private JTextField title;
   private JTextArea list;

   public ReadingList() {
      super("Reading List");
      setSize(WIDTH, HEIGHT);
      setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

      JPanel main = new JPanel();
      main.setLayout(new BorderLayout(8, 8));
      main.setBorder(BorderFactory.createEmptyBorder(10, 10, 10, 10));
      getContentPane().add(main);

      // NORTH: label, text field and Add button inside a titled border
      JPanel entry = new JPanel();
      entry.setBorder(BorderFactory.createTitledBorder("Add a book"));
      entry.add(new JLabel("Title:"));
      title = new JTextField(20);
      entry.add(title);
      JButton add = new JButton("Add");
      add.addActionListener(this);
      entry.add(add);
      main.add(entry, BorderLayout.NORTH);

      // CENTER: the list itself, scrollable
      list = new JTextArea(10, 30);
      list.setEditable(false);
      JScrollPane scroll = new JScrollPane(list);
      scroll.setBorder(BorderFactory.createTitledBorder("My list"));
      main.add(scroll, BorderLayout.CENTER);

      // SOUTH: one button
      JPanel buttons = new JPanel();
      JButton clear = new JButton("Clear");
      clear.addActionListener(this);
      buttons.add(clear);
      main.add(buttons, BorderLayout.SOUTH);
   }

   public void actionPerformed(ActionEvent e) {
      String command = e.getActionCommand();
      if (command.equals("Add")) {
         list.append(title.getText() + "\n");
         title.setText("");
      } else if (command.equals("Clear")) {
         list.setText("");
      }
   }

   public static void main(String args[]) {
      ReadingList gui = new ReadingList();
      gui.setVisible(true);
   }
}

Lecture Summary
  • A border is an object that decorates the edge of a component. Any JComponent can have one: component.setBorder(someBorder);.
  • BorderFactory is a class of static methods that build borders: createLineBorder, createTitledBorder, createEtchedBorder, createRaisedBevelBorder and createLoweredBevelBorder, createEmptyBorder, createCompoundBorder. The factory is in javax.swing; the Border interface and the border classes are in javax.swing.border.
  • A border is drawn inside the component, so it shrinks the interior by its insets. A compound border's insets are the sum of its two parts — and the argument order changes the picture, not the arithmetic.
  • createEmptyBorder(top, left, bottom, right) draws nothing and is the standard way to put a margin round a group of components. Wrapping a visible border round it with createCompoundBorder is the standard way to get a caption and breathing room.
  • getContentPane() returns a java.awt.Container, which has no setBorder. Put a JPanel inside the content pane and border that.
  • An ImageIcon loads a picture from a file and can be given to a JLabel, a JButton or a JMenuItem. setHorizontalTextPosition and setVerticalTextPosition move the text relative to the picture.
  • A missing image file throws nothing. The icon is constructed, reports a width of −1 and a load status of MediaTracker.ERRORED, and the component simply draws no picture. Check getIconWidth() < 0 when it matters.
  • A JScrollPane wraps one component so it can scroll: new JScrollPane(textArea). Add the scroll pane to the window, not the component — adding the component moves it out of the viewport and leaves you with neither scroll bars nor an error message.
  • Two policies, three constants each: AS_NEEDED (the default), ALWAYS, NEVER. The policy controls the bar, not whether the view scrolls.
  • A complete GUI class is always the same eight steps: header, fields for whatever the listener touches, frame setup, one bordered main panel, regions, borders, one actionPerformed, a two-line main.
