Everything CSCI 111 taught you, respelled in Java. Not one of the 28 classes — read it if CSCI 111 feels far away, or if you took it in C++ and want the Java spelling.

What this page is for

CSCI 111 at Queens is taught in C++. CSCI 212 is a Java course. That single fact is the reason this page exists.

You are not missing any concepts. You already know what a variable is, what an if does, how a loop repeats, what a function returns, how an array is indexed. 1.The Java program skeleton, and printing

This section is deliberately the shortest one on the page, because Lecture 1 takes the skeleton apart word by word, explains what the JVM is, and shows you what javac says when you get it wrong. All you need here is enough to make the rest of the page readable.

In C++ you could write int main() at the top level of a file and be done. Java does not allow a free-floating function. Every method must live inside a class, so the smallest Java program is still a class with a method in it.

C++ (CSCI 111) — for comparison only

#include <iostream>
using namespace std;

int main() {
    cout << "CSCI 111";
    cout << " -> ";
    cout << "CSCI 212" << endl;
    return 0;
}

And the same program in Java. There is no #include, no using namespace, and no return 0;.

Refresher.java

public class Refresher {
    public static void main(String args[]) {
        System.out.print("CSCI 111");
        System.out.print(" -> ");
        System.out.println("CSCI 212");
        System.out.println("Same ideas.");
        System.out.println("New spelling.");
    }
}
CSCI 111 -> CSCI 212
Same ideas.
New spelling.

Two words of that skeleton are worth a sentence each right now; Lecture 1 does the rest properly.

PieceThe one-line version
public class RefresherA named container. The file must be called Refresher.java — same spelling, same capitalization.
public static void main(String args[])The method the JVM starts at. It is Java's int main(). The signature is fixed; change one word and the program compiles but will not start.
System.out.print(x)cout << x. Writes x and stops.

Common Mistake— the file name must match the public class

C++ let you name the file anything you liked. Java does not. Put public class Refresher111 in a file called Hello.java and javac refuses before it looks at anything else:

Hello.java:1: error: class Refresher111 is public, should be declared in a file named Refresher111.java
public class Refresher111 {
       ^
1 error

Read the message — it tells you the exact file name it wants. This is the single most common first-week error in this course, and it costs nothing but a rename.

The rest of the workflow is two commands rather than one: javac Refresher.java compiles (silence means success), then java Refresher runs — note the class name, with no extension.

2.Variables, types and arithmetic

Definition— variable, type, declaration

A variable is a named box in memory holding one value. Its type says what kind of value fits and how many bits the box takes. A declaration is the statement that creates the box: int count = 12;.

All of that is exactly what it was in CSCI 111. Java changes three small things: the sizes are fixed on every machine, a local variable must be given a value before you read it (the compiler enforces this), and the string type is spelled String with a capital S because it is a class, not a primitive.

Java has eight primitive types — the only things in Java that are not objects. Four of them will cover almost everything you write this semester.

Declarations themselves are almost character-for-character what you wrote last semester:

double price   = 4.75;
char   grade   = 'B';

Worked Example— declaring, updating, and dividing

This program declares one of each type, then updates count three different ways, then divides. Before you open the toggle, work out what count is by the time it is printed the second time, and decide what count / 5 and count / 5.0 will each give.

Vars.java

public class Vars {
    public static void main(String args[]) {
        int    count   = 12;
        double price   = 4.75;
        char   grade   = 'B';
        boolean passed = true;
        String name    = "Queens";

        System.out.println("count   = " + count);
        System.out.println("price   = " + price);
        System.out.println("grade   = " + grade);
        System.out.println("passed  = " + passed);
        System.out.println("name    = " + name);

        count = count + 1;
        count += 5;
        count++;
        System.out.println("count is now " + count);

        System.out.println("total   = " + count * price);
        System.out.println("integer = " + count / 5);
        System.out.println("real    = " + count / 5.0);
        System.out.println("left    = " + count % 5);
    }
}

count starts at 12, then + 1 makes it 13, += 5 makes it 18, and ++ makes it 19. The three forms are just increasingly short ways of writing the same idea, and they are the same three forms you used in C++.

ExpressionResultWhy
count * price90.25int times double — the int is promoted, so the answer is a double.
count / 53Both operands are int, so this is integer division: 19 ÷ 5 = 3, remainder thrown away.

Notice "total = " + count * price prints 90.25, not a concatenation of 19 and 4.75. * binds tighter than +, so the multiplication happens first. That is not always what you want — see the Quick Check below.

Key Idea— the operands decide the operation, not the destination

If both operands of / are integers, Java does integer division and throws the remainder away. If either operand is a double, it does real division. The type you are about to assign the answer to has no say in it:

double average = (90 + 85 + 78) / 3;      // 84.0  -- the division was already integer
double correct = (90 + 85 + 78) / 3.0;    // 84.33333333333333

This is identical to C++, and it is still the single most common source of "why is my answer zero?" Writing 3.0 instead of 3 is the whole fix.

Key Idea— + is overloaded, and it reads left to right

Java has no << for output. You build one String with + and hand it to println. But + also means addition, and which one you get depends on whether a String has appeared yet, scanning left to right:

  • "n = " + 1 + 2 is n = 12 — the String came first, so both + concatenate.
  • 1 + 2 + " is n" is 3 is n — the numbers added before any String appeared.
  • "n = " + (1 + 2) is n = 3 — the parentheses force the addition to happen first.

When you are labelling a computed value, parenthesise the computation. Always.

Quick Check R.2

Let int total = 7, count = 2;. Give the exact printed text for each statement.

(a) System.out.println(total / count);

3. Both are int, so integer division: 7 ÷ 2 is 3, remainder discarded.

(b) System.out.println(total % count);

1. The remainder part (a) threw away.

(c) System.out.println((double) total / count);

3.5. The cast binds tighter than /, so it applies to total alone and the division is real. total / 2.0 gives the same answer.

(d) System.out.println((double) (total / count));

3.0. The parentheses make the integer division happen first, giving 3; widening 3 to a double afterwards cannot recover the lost half. Compare with (c) — same symbols, different parentheses, different answer.

(e) System.out.println("total/count = " + total / count);

total/count = 3. / binds tighter than +, so the division happens and only then is the result concatenated.

(f) System.out.println("total/count = " + total + count);

total/count = 72. There is no arithmetic here at all. Left to right, "total/count = " + total is already a String, so + count just appends the character 2 after the 7.

Things to notice across all six parts. All six were verified by running them. Parts (c) and (d) differ only in where the parentheses sit; (e) and (f) differ only by a / that is not there. On an exam these pairs are a point each and cost nothing but care. Annotate the type of each subexpression as you read: writing a small int, double or String above each operator turns the whole question into bookkeeping.

Quick Check R.3

Write a complete program Change.java that starts with int cents = 1287; and prints two lines: how many whole dollars and how many leftover cents that is, and the same amount written as a decimal number of dollars. Use / and % for the first line.

Plan. "How many whole dollars" is exactly what integer division gives you, so cents / 100 is the right tool and the truncation is wanted here rather than being a bug. cents % 100 is the part that division threw away, which is precisely the leftover cents. The second line needs real division, so divide by 100.0.

Change.java

public class Change {
    public static void main(String args[]) {
        int cents = 1287;

        int dollars = cents / 100;
        int leftover = cents % 100;

        System.out.println(cents + " cents is " + dollars + " dollars and " + leftover + " cents");
        System.out.println("As a decimal amount: " + cents / 100.0);
    }
}
1287 cents is 12 dollars and 87 cents
As a decimal amount: 12.87

Things to notice. The / and % pair is the classic "split a number into two parts" idiom, and you will use it constantly: seconds into minutes and seconds, an index into a row and a column, a number into its digits. Whenever you see one of the pair you should expect the other nearby.

On the first line, every + is a concatenation because the leftmost operand cents meets a String immediately — cents + " cents is " makes the whole rest of the expression textual. That is why dollars and leftover print as text and nothing is accidentally added together.

3.Decisions

if, else if, else and switch are written in Java exactly as you wrote them in C++. Same braces, same parentheses, same && || !, same == != < <= > >=. There is one real difference, and it is the first thing in this section because it is the one that bites.

Warning— a Java condition must be a boolean

In C++ a condition is really a number, and zero counts as false. That is why if (n) works and why if (n = 5) compiles. Java has no such rule: the thing inside the parentheses must have type boolean and nothing else will do.

CondInt.java:4: error: incompatible types: int cannot be converted to boolean
        if (count) System.out.println("nonzero");
            ^
1 error

Two C++ habits therefore stop working, and both stop working at compile time, which is a gift:

  • if (n) meaning "if n is nonzero" — write if (n != 0).
  • if (n = 5) — the classic typo for ==. In C++ this compiles, always takes the branch, and quietly overwrites n. In Java it is the error above, every time.

Anything genuinely two-valued should be a boolean variable in the first place: boolean passed = true;, then if (passed). Do not keep an int that is 0 or 1 — Java will not let you use it as a condition anyway.

Key Idea— an else if chain stops at the first match

The conditions in an if / else if / else chain are tested in order, and the moment one is true its block runs and the entire rest of the chain is skipped. That is different from writing several separate if statements, where every condition is tested.

Which is why order matters enormously in a grading program — test the most restrictive case first. Exactly the same rule as C++; only the printing changed.

Worked Example— a chain, two logical operators, and a switch

Three separate decisions in one program. Before you reveal: score is 87, so which branch of the chain runs? And does the second if print anything?

Decisions.java

public class Decisions {
    public static void main(String args[]) {
        int score = 87;

        if (score >= 90)      System.out.println("A");
        else if (score >= 80) System.out.println("B");
        else if (score >= 70) System.out.println("C");
        else                  System.out.println("Below C");

        boolean enrolled = true;
        int credits = 12;
        if (enrolled && credits >= 12) System.out.println("Full time");
        if (!enrolled || credits == 0) System.out.println("Not attending");

        char letter = 'B';
        switch (letter) {
            case 'A': System.out.println("4.0"); break;
            case 'B': System.out.println("3.0"); break;
            case 'C': System.out.println("2.0"); break;
            default:  System.out.println("no points");
        }
    }
}
B
Full time
3.0

Three lines, one from each decision.

  • score is 87, so score >= 90 fails and score >= 80 succeeds. B prints and the chain is finished — the score >= 70 test, which is also true, is never even evaluated.
  • enrolled && credits >= 12 is true && true, so Full time prints. !enrolled || credits == 0 is false || false, so the second if prints nothing. && and || short-circuit in Java exactly as in C++: if the left side of && is false, the right side is never evaluated at all.
  • The switch matches case 'B', prints 3.0, and the break jumps out. Without that break control would fall through into case 'C' and print 2.0 as well.

One note on switch that differs from what you may remember: Java lets you switch on an int, a char, a String or an enum. Switching on a String is legal and common, and case "quit": works. You still need break at the end of every case unless you deliberately want fall-through.

Quick Check R.4

A student scores 95. Predict the complete output of this program, then say what is wrong with the first decision.

BadOrder.java

public class BadOrder {
    public static void main(String args[]) {
        int score = 95;

        if      (score >= 70) System.out.println("C");
        else if (score >= 80) System.out.println("B");
        else if (score >= 90) System.out.println("A");
        else                  System.out.println("F");

        if (score >= 70) System.out.println("at least C");
        if (score >= 80) System.out.println("at least B");
        if (score >= 90) System.out.println("at least A");
    }
}

Plan. Handle the two decisions separately, because they behave differently on purpose. The first is a chain, so exactly one branch runs — the first whose test is true. The second is three independent if statements, so every test is evaluated.

C
at least C
at least B
at least A

What is wrong. The chain is ordered from least restrictive to most. A 95 satisfies score >= 70 immediately, so it prints C and the >= 80 and >= 90 tests are never reached. The A branch in this program is unreachable for every possible score: any value that would satisfy score >= 90 also satisfies score >= 70, so the chain always stops first.

The fix is to reverse the order, most restrictive first, exactly as Decisions.java above does it.

Things to notice. The second half of the program shows why the distinction matters. Three separate if statements are not a chain: all three conditions are true for a 95, so all three lines print. Use a chain when you want exactly one outcome; use separate if statements when the tests are genuinely independent.

Quick Check R.5

Write a complete program Leap.java containing a method public static boolean isLeap(int year) that returns whether year is a leap year, and a main that tests it on 1900, 2000, 2023, 2024 and 2100.

The rule: a year is a leap year if it is divisible by 4, except that years divisible by 100 are not, except that years divisible by 400 are.

Plan. Turn the English into one boolean expression rather than a nest of if statements. "Divisible by 4 but not by 100" is year % 4 == 0 && year % 100 != 0. "Or divisible by 400" is a separate way of qualifying, so join it with ||. Because the method's job is to answer a yes/no question, its return type is boolean and you can return the expression directly — there is no need for if (...) return true; else return false;.

Leap.java

public class Leap {
    public static boolean isLeap(int year) {
        return (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
    }

    public static void main(String args[]) {
        int years[] = {1900, 2000, 2023, 2024, 2100};
        for (int y : years) {
            System.out.println(y + " leap? " + isLeap(y));
        }
    }
}
1900 leap? false
2000 leap? true
2023 leap? false
2024 leap? true
2100 leap? false

Things to notice. The parentheses around the && part are not strictly required — && binds tighter than || in Java just as in C++ — but write them anyway. Nobody reading the line should have to remember a precedence table.

1900 and 2100 are the interesting cases: both are divisible by 4, both are divisible by 100, neither is divisible by 400, so both are false. 2000 is divisible by 400, so the right side of the || rescues it. If you test only 2023 and 2024 your code looks correct and is not.

for (int y : years) is the for-each loop — "for each int y in years". It is new syntax with no C++ equivalent you were taught, and section 6 comes back to it.

4.Loops

This is the section with the least to relearn. for, while, do-while, break and continue are written in Java character-for-character as they were in C++, including the two semicolons in the for header and the trailing semicolon on do { } while (...);.

Definition— the three loop shapes
  • for (setup; test; change) — the counting loop. Use it when you know up front how many times you are going round, or when you are walking an array by index. The counter declared in the header exists only inside the loop.
  • while (test) — the test comes first, so the body may run zero times. Use it when the stopping point is discovered as you go.
  • do { } while (test); — the test comes last, so the body always runs at least once. Use it for "do this, then ask whether to do it again".

Two statements steer a loop from inside it: break leaves the loop immediately, and continue skips the rest of this pass and goes straight to the next one. Both apply to the innermost loop containing them.

Worked Example— all three shapes, plus break, continue and nesting

Five loops in one program. Before you reveal, answer two questions: what is the first power of 2 that is at least 50, and which multiples of 3 does the fourth loop actually add up?

Loops.java

public class Loops {
    public static void main(String args[]) {
        for (int i = 1; i <= 5; i++) System.out.print(i + " ");
        System.out.println();

        int n = 1;
        while (n < 50) n = n * 2;
        System.out.println("first power of 2 at least 50: " + n);

        int tries = 0;
        do {
            tries++;
        } while (tries < 3);
        System.out.println("do-while ran " + tries + " times");

        int total = 0;
        for (int i = 1; i <= 100; i++) {
            if (i % 3 != 0) continue;
            if (i > 20) break;
            total += i;
        }
        System.out.println("multiples of 3 up to 20 sum to " + total);

        for (int row = 1; row <= 3; row++) {
            for (int col = 1; col <= 3; col++) System.out.print(row * col + "\t");
            System.out.println();
        }
    }
}

  • The counting loop prints 1 2 3 4 5 with a trailing space, because every number is followed by " ". The bare println() afterwards ends the line.
  • The while loop overshoots, and that is correct. The powers go 1, 2, 4, 8, 16, 32, 64. When n is 32 the test n < 50 is still true, so the body runs once more and n becomes 64. A while loop always exits after the condition has failed, never at the last value that satisfied it.
  • The do-while runs three times. tries goes 1, 2, 3, and the test fails when it reaches 3. Note that it would still have run once even if tries had started at 99 — that is the whole point of the shape.
  • continue and break together. continue skips every i that is not a multiple of 3. break stops the loop entirely the first time a multiple of 3 exceeds 20, which is 21. So the values actually added are 3, 6, 9, 12, 15 and 18, and 3+6+9+12+15+18 = 63. The header says i <= 100, but the loop never gets past 21.
  • The nested loops print a 3×3 multiplication table. The inner loop runs completely for each single pass of the outer loop, and \t is a tab, exactly as in C++.
Common Mistake— the semicolon that empties a loop

for (int i = 0; i < 5; i++); compiles cleanly and does nothing five times, because the ; is the loop body. Whatever block you wrote after it runs exactly once. Java does not warn about this any more than C++ did, so when a loop appears to run once, look at the end of its header line first.

Quick Check R.7

Write a complete program Stars.java that prints a left-aligned triangle of asterisks five rows tall: one star on the first row, two on the second, up to five on the fifth.

5.Methods, and pass-by-value

This is the most important section on the page. Not because methods are hard — they are the functions you already write — but because the last part of it, pass-by-value, is the idea that Lecture 8 builds its whole treatment of object references on. If you read one section here, read this one.

Definition— method

A method is Java's word for a function. The behaviour is identical to a C++ function; the difference is location. There is no such thing as a free-floating function in Java — every method lives inside a class.

The vocabulary carries over unchanged. The return type is the type of the value handed back, or void if nothing is handed back. Parameters are the variables named in the method's own header. Arguments are the values you pass at the call site, which get copied into the parameters.

Here is a title line, word by word. Four of these five pieces you already understand from C++; only static is new, and even that is only new as a word.

public static int square(int x) {
    return x * x;
}
WordWhat it is doing
publicVisible from outside this class. For now, write public on everything.
staticThe method belongs to the class itself rather than to any object of it. Until Lecture 7 you have no objects, so every method you write is static. A non-static method cannot be called from main without an object, and forgetting this is the classic first-month error.
intThe return type — the type of the value this method hands back. void if it hands nothing back.
squareThe method's name. Java convention is lowerCamelCase.
(int x)The parameter list: one parameter named x, of type int. Empty parentheses mean no parameters.

Calling it is exactly what you would expect: square(7) is an expression whose value is 49, so you can print it, store it, or use it in arithmetic. Compare the C++ you already know:

C++ (CSCI 111) — for comparison only

int square(int x) {
    return x * x;
}

Two differences: the words public static in front, and the fact that in Java this must sit inside a class. Nothing else changed.

Worked Example— three methods, and the pass-by-value question

The first half of this program is ordinary: a method that returns an int, a void method that prints, and a method that returns a double. The second half is the part to think hard about.

bump adds 100 to its parameter. bumpAll adds 100 to element 0 of its parameter. Before you reveal: after bump(x) returns, what is x? And after bumpAll(nums) returns, what is nums[0]? Commit to both answers before opening the toggle.

Methods111.java

public class Methods111 {
    public static int square(int x) {
        return x * x;
    }

    public static void banner(String text) {
        System.out.println("=== " + text + " ===");
    }

    public static double average(int a, int b, int c) {
        return (a + b + c) / 3.0;
    }

    public static void main(String args[]) {
        banner("Methods");
        System.out.println("square(7)      = " + square(7));
        System.out.println("average(3,4,5) = " + average(3, 4, 5));

        int x = 5;
        bump(x);
        System.out.println("after bump(x), x is still " + x);

        int nums[] = {4, 1, 9};
        bumpAll(nums);
        System.out.println("after bumpAll, nums[0] is " + nums[0]);
    }

    public static void bump(int value) {
        value = value + 100;
    }

    public static void bumpAll(int values[]) {
        values[0] = values[0] + 100;
    }
}

square(7)      = 49
average(3,4,5) = 4.0

after bumpAll, nums[0] is 104

The two lines that matter are the last two, and the pair of them looks like a contradiction until you see what is actually being copied.

CallWhat gets copied into the parameterWhat the method changesEffect on the caller
bump(x)the number 5its own private copy, now 105none — x is still 5
bumpAll(nums)the arrow pointing at the arrayelement 0 of the array the arrow points tovisible — nums[0] is 104

Nothing special happened for arrays. Java copied the argument in both cases — it always copies. The difference is what the variable holds. An int variable holds a number, so a copy of it is a second, independent number. An array variable holds a reference: an arrow to an array that lives elsewhere. Copying the arrow gives you a second arrow to the same array. Follow either arrow and you reach the same five boxes.

Note also average(3, 4, 5) printing 4.0 rather than 4. The method returns a double, and Java always prints a double with a decimal point — even when the value is whole. C++ would have printed 4. That is a formatting difference between the languages, not an arithmetic one.

Finally, notice that bump and bumpAll are declared after main and called from inside it, with no forward declaration and no prototype. Java reads the whole class before it compiles any of it, so the order of methods in a file never matters. That is one C++ chore you can forget about.

Key Idea— Java is pass-by-value, always, with no exceptions

Every argument in Java is copied into the parameter. There is no & reference parameter as in C++, no way to opt out, no out keyword. Which gives you exactly two rules, and they are enough to answer every question of this kind:

  1. A method can never change which value the caller's variable holds. Assigning to a parameter changes only the method's own copy.
  2. A method can change the contents of an object the caller's variable points at — an array, or later a Point, a Ticket, an ArrayList — because both variables point at the same thing.

Say it as a sentence: you cannot repoint the caller's arrow, but you can repaint what it points at. Lecture 8 spends the whole session on the second rule for objects; this is where it starts.

Common Mistake— trying to write swap the C++ way

In C++ you could write void swap(int &a, int &b) and the caller's two variables really were exchanged. There is no Java translation of that signature. void swap(int a, int b) compiles, runs, exchanges its own two copies, and leaves the caller untouched — a method that appears to work and does nothing. Quick Check R.8 shows exactly that happening.

When you need a method to hand back a changed value, return it. When you need it to hand back two, put them in an array (or, from Lecture 7, in an object).

Quick Check R.8

Predict every line of output. The class has two methods named swap — one takes two int values, the other takes an int array.

SwapFail.java

public class SwapFail {
    public static void swap(int a, int b) {
        int temp = a;
        a = b;
        b = temp;
        System.out.println("inside swap:  a = " + a + ", b = " + b);
    }

    public static void swap(int pair[]) {
        int temp = pair[0];
        pair[0] = pair[1];
        pair[1] = temp;
    }

    public static void main(String args[]) {
        int x = 1, y = 2;
        swap(x, y);
        System.out.println("back in main: x = " + x + ", y = " + y);

        int pair[] = {1, 2};
        swap(pair);
        System.out.println("after array swap: " + pair[0] + " " + pair[1]);
    }
}

Plan. Ask the same question at each call: what was copied into the parameter? For swap(x, y) it was two numbers. For swap(pair) it was an arrow.

inside swap:  a = 2, b = 1
back in main: x = 1, y = 2
after array swap: 2 1

Things to notice. The first swap genuinely works — look at line 1, a and b really were exchanged. It just exchanged the method's own two copies, and when the method returned those copies ceased to exist. That is the cruel part: the method is not broken, it is doing precisely what you told it to, and the caller sees nothing.

The array version works because both pair in main and pair in the method are arrows to the same two boxes. The method never assigns to the parameter itself; it assigns to pair[0] and pair[1], which is reaching through the arrow.

Try this on paper: add the line pair = new int[]{99, 99}; at the top of the array swap. Now the method repoints its own arrow at a brand-new array, scrambles that, and main still prints 1 2 — rule 1 again. Repointing the parameter is invisible to the caller; reaching through it is not.

Two methods here share the name swap and differ only in their parameter lists. That is overloading, and it is legal in Java exactly as in C++. Lecture 2 covers it properly.

Quick Check R.9

Write a complete program MaxOf.java with two methods and a main that uses them:

  • public static int maxOf(int values[]) — returns the largest element.
  • public static double averageOf(int values[]) — returns the mean, as a decimal.

Test both on {14, 3, 27, 8, 27, 1}. Neither method may print anything.

Plan. For maxOf, take the first element as the best-so-far and compare every later one against it. Starting from values[0] rather than from 0 matters: an array of negative numbers would defeat a best = 0; start. Because we have already used index 0, the loop begins at index 1.

For averageOf, accumulate the sum in an int — that part really is integer arithmetic — and make the division real by casting one operand: total / (double) values.length. Do not write total / values.length and hope the double return type saves you; it will not.

Both methods return rather than print, which is what lets main decide the wording, and what would let you reuse them in a different program tomorrow.

MaxOf.java

public class MaxOf {
    public static int maxOf(int values[]) {
        int best = values[0];
        for (int i = 1; i < values.length; i++) {
            if (values[i] > best) best = values[i];
        }
        return best;
    }

    public static double averageOf(int values[]) {
        int total = 0;
        for (int v : values) total += v;
        return total / (double) values.length;
    }

    public static void main(String args[]) {
        int data[] = {14, 3, 27, 8, 27, 1};
        System.out.println("max     = " + maxOf(data));
        System.out.println("average = " + averageOf(data));
    }
}
max     = 27
average = 13.333333333333334

Things to notice. The two loops are written differently on purpose. maxOf needs an index, because it starts at 1 rather than 0, so it uses a counting for. averageOf only needs each value, never its position, so it uses the for-each loop for (int v : values). Reach for for-each whenever you do not care where you are in the array — it is shorter and it cannot go out of bounds.

Neither method changes the array, and that is worth noticing given the previous Quick Check: both could have, since both received an arrow to the caller's data. A method that only reads should only read. In C++ you would say const; Java has no equivalent for a parameter, so the discipline is yours to keep.

27 appears twice and maxOf returns it once, which is correct — > rather than >= means the first of two equal maxima wins, and the answer is the same either way.

6.Arrays, Strings and Scanner input

Three things in one section because they are the three that a CSCI 111 program could not do without, and all three are spelled differently in Java.

Arrays

Definition— array

An array is a fixed-length run of boxes of the same type, sharing one name, reached by an index that starts at 0. All of that is unchanged from C++. Two things are different:

  • An array in Java is an object. You create it with new, and the variable holds a reference to it — the arrow from section 5.
  • The array knows its own size, and you read it with .length — a field, with no parentheses. You never pass the size around as a second parameter the way you had to in C++.

The three ways to make one, and the difference between them:

int scores[] = new int[5];              // five int boxes, all set to 0
int[] scores2 = new int[5];             // identical -- the brackets may go either side
int digits[] = {3, 1, 4, 1, 5};         // size deduced from the list: an int[5]
String names[] = {"Ana", "Bo", "Cy"};   // works for any type

Note the third difference from C++: new int[5] does initialize, filling every box with 0 (or 0.0, or false, or null for object types). C++ left the boxes full of garbage. You still cannot read past the end — but Java's reaction to that is very different, as the worked example shows.

Worked Example— building, walking, and running off the end

This program fills an array, sums it, finds its maximum, walks a second array with a for-each loop, and then deliberately reads one element past the end. Before you reveal, answer two questions: what is the average of 90, 85, 78, 92 and 66, and what does the last line do?

Arrays111.java

public class Arrays111 {
    public static void main(String args[]) {
        int scores[] = new int[5];
        scores[0] = 90; scores[1] = 85; scores[2] = 78; scores[3] = 92; scores[4] = 66;

        String names[] = {"Ana", "Bo", "Cy"};

        System.out.println("scores.length = " + scores.length);
        System.out.println("names.length  = " + names.length);

        int total = 0;
        for (int i = 0; i < scores.length; i++) total += scores[i];
        System.out.println("total   = " + total);
        System.out.println("average = " + total / (double) scores.length);

        int high = scores[0];
        for (int i = 1; i < scores.length; i++) {
            if (scores[i] > high) high = scores[i];
        }
        System.out.println("highest = " + high);

        for (String s : names) System.out.print(s + " ");
        System.out.println();

        System.out.println("about to read scores[5] ...");
        System.out.println(scores[5]);
    }
}
scores.length = 5
names.length  = 3
total   = 411
average = 82.2
highest = 92
Ana Bo Cy 
about to read scores[5] ...
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
	at Arrays111.main(Arrays111.java:26)

Everything above the last two lines is ordinary. Three details are worth pulling out:

  • scores.length has no parentheses. Writing scores.length() is a compile error — see Quick Check R.10.
  • The loop bound is i < scores.length, never i <= scores.length. Valid indices run 0 through length - 1, so < is the correct comparison and <= is the classic off-by-one.
  • total / (double) scores.length is real division and gives 82.2. Without the cast, 411 / 5 would be the int 82, and the .2 would be gone before the assignment.
  • for (String s : names) is the for-each loop: "for each String s in names". It has no index at all, which is exactly why it cannot run off the end. Use it whenever you do not need to know where you are.

The last line is the point of the example. scores has five boxes, indices 0 through 4. There is no scores[5]. In C++ that line compiles, runs, reads whatever bytes happen to sit past the end of the array, and prints something — possibly a plausible-looking number, possibly a different one every run. The bug is invisible and may not surface for weeks.

Java checks every index at run time. The read never happens; the JVM throws an ArrayIndexOutOfBoundsException, prints exactly which index and which length, names the file and line number, and stops the program. That is not the program failing gracelessly — that is Java refusing to let a memory bug become your problem in six weeks' time.

Warning— read the exception, it tells you everything

Index 5 out of bounds for length 5 names the offending index and the actual length, and Arrays111.main(Arrays111.java:26) names the file and the exact line. There is no debugging to do here beyond reading the message.

Two habits prevent almost every one of these: write i < a.length rather than any hand-counted number, and use the for-each loop whenever the index is not actually needed.

Strings

Definition— String

A String is a sequence of characters written in double quotes. Unlike C++'s string, Java's String is a class, spelled with a capital S, and it is one of the few classes you may use without importing anything. Everything you do to one is a method call, written with a dot: name.length(), name.toUpperCase().

A String is also immutable — no method ever changes it; every one returns a new String. Lecture 4 is devoted to the class, and this is only the handful you need to read the rest of this page.

Common Mistake— comparing Strings with ==

In C++, s1 == s2 on two string values compares their characters. In Java, == on two String variables compares the two arrows — it asks whether they point at the same object, not whether they spell the same thing. Use .equals:

StringEquals.java

public class StringEquals {
    public static void main(String args[]) {
        String typed = "Que" + "ens";
        String built = new String("Queens");

        System.out.println("typed == built     : " + (typed == built));
        System.out.println("typed.equals(built): " + typed.equals(built));
    }
}
typed == built     : false
typed.equals(built): true

Both variables spell Queens, and == still says false, because new String(...) deliberately builds a second object. The rule to carry away is short: compare Strings with .equals, never with ==. Lecture 4 explains why == sometimes appears to work (Java shares identical literals behind your back), which is exactly what makes the habit dangerous rather than merely wrong.

Reading input with Scanner

Definition— Scanner

Scanner is Java's replacement for cin. You create one, attached to System.in, and then call a method for each thing you want to read. It lives in java.util, so the file needs import java.util.Scanner; above the class — the nearest thing Java has to an #include.

C++ (CSCI 111)Java (CSCI 212)
cin >> n; for an intint n = input.nextInt();
cin >> x; for a doubledouble x = input.nextDouble();
cin >> word; one wordString word = input.next();
getline(cin, line); a whole lineString line = input.nextLine();

Notice the shape of the change. cin >> fills a variable you already declared; a Scanner method returns the value, so you assign it. That is the same print-versus-return distinction from section 5, showing up again.

Worked Example— a whole line, then a number

This program asks for a name (which may contain a space, so nextLine) and then an age (nextInt), and uses two String methods on the answer.

One thing to know before you read the output: this program was run with its input piped in (the two lines Ada Lovelace and 19 fed to it from a file) rather than typed at a keyboard. That has two visible consequences. The typed text is not echoed, so you will not see Ada Lovelace after the prompt. And because print does not end a line, the two prompts run together on a single line with the first line of real output. When you run it and type the answers, each prompt will be followed by what you typed and then a line break.

Strings111.java

import java.util.Scanner;

public class Strings111 {
    public static void main(String args[]) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter your name: ");
        String name = input.nextLine();
        System.out.print("Enter your age: ");
        int age = input.nextInt();

        System.out.println("Hello, " + name + ".");
        System.out.println("Next year you will be " + (age + 1) + ".");
        System.out.println("Your name has " + name.length() + " characters.");
        System.out.println("In capitals: " + name.toUpperCase());
        input.close();
    }
}
Enter your name: Enter your age: Hello, Ada Lovelace.
Next year you will be 20.
Your name has 12 characters.
In capitals: ADA LOVELACE
  • Both prompts sit on the first line of output, followed immediately by Hello, Ada Lovelace. — that is the piped-input artefact described above, not a bug in the program.
  • (age + 1) is parenthesised. Without the parentheses, "...be " + age + 1 would print be 191, because a String had already appeared and both + would concatenate.
  • name.length() is 12: Ada Lovelace is eleven letters plus the space. nextLine reads the whole line including the space, which is precisely why it was used instead of next().
  • toUpperCase() returns a new String; name itself is unchanged, because a String is immutable. Printing name again afterwards would still show Ada Lovelace.
Warning— nextInt() followed by nextLine() eats the rest of the line

This one bites every CSCI 212 student in the first two weeks, and it does not look like a bug — the program runs, prints no error, and gives a wrong answer. Read the program, then the output.

ScannerTrap.java

import java.util.Scanner;

public class ScannerTrap {
    public static void main(String args[]) {
        Scanner input = new Scanner(System.in);
        System.out.print("Age: ");
        int age = input.nextInt();
        System.out.print("Name: ");
        String name = input.nextLine();
        System.out.println("age  = [" + age + "]");
        System.out.println("name = [" + name + "]");
        input.close();
    }
}

Run with 19 on the first line and Ada on the second, piped in as before:

Age: Name: age  = [19]
name = []

name is empty. The user never got a chance to answer the second question, and the program did not wait.

Why. nextInt() reads the digits 19 and stops there. The newline you pressed after typing 19 is still sitting in the input, unread. nextLine() then does exactly what it is told: it reads from the current position to the end of the current line — which is nothing at all, just that leftover newline. It returns the empty string immediately, without waiting for anything.

The fix. Consume the leftover newline with an extra nextLine() whose result you throw away:

int age = input.nextInt();
input.nextLine();                 // consume the rest of the number's line
String name = input.nextLine();   // now this reads the line you meant

The rule is easy to remember once you have the picture: after any nextInt() or nextDouble(), add a bare input.nextLine(); before the next nextLine(). Mixing next()/nextInt() with nextLine() is the only situation where this arises — a run of nextInt() calls, or a run of nextLine() calls, is always fine.

Quick Check R.10

Given these two declarations:

String word = "Queens";
int digits[] = {3, 1, 4, 1, 5};

say precisely what happens for each of the following — a compile error, a run-time exception, or a value.

(a) System.out.println(word.length);

A compile error. length on a String is a method, so it needs parentheses. javac says:

        System.out.println(word.length);
                               ^

Read the last two lines of the message: it looked for a variable called length on a String and found none. Write word.length().

(b) System.out.println(digits.length());

A compile error, the exact mirror image of (a). length on an array is a field, so the parentheses are wrong:

                                 ^
  symbol:   method length()
  location: variable digits of type int[]

This time it says it looked for a method length() and found none. Write digits.length.

(c) System.out.println(digits[digits.length]);

This compiles, and then throws at run time. digits.length is 5, so the line asks for digits[5] — one past the last valid index, which is 4. You get an ArrayIndexOutOfBoundsException reading Index 5 out of bounds for length 5, exactly as in the worked example above, and the program stops there.

The last element is digits[digits.length - 1].

(d) for (int d : digits) System.out.print(d);

A value: it prints 31415 on one line, with no separator and no newline, because print was used rather than println.

Things to notice across all four parts. Parts (a) and (b) are compile errors, so the compiler finds them for you the first time you build. Part (c) compiles cleanly and fails only when that line is actually reached — which might be on an input you never tested. That is the whole difference between a compile-time error and a run-time exception, and it is why the for-each loop in (d) is worth preferring: with no index, there is nothing to get wrong.
